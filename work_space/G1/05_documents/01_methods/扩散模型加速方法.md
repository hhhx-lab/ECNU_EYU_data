# 扩散模型加速方法

针对已训练好的 EDM (Karras et al. 2022) 扩散模型，在不重新训练的前提下可采用的推理加速方法。

当前基线：EDM Heun 2nd-order ODE solver，默认 18 步采样（36 NFE），3D UNet (channels=48,96,192,384)，crop_size=64³，4 模态逐病灶串行推理。

---

## 一、高阶 ODE Solver 替换

### 1.1 DPM-Solver++ (Lu et al. 2022)

**原理**：扩散 ODE `dx/dσ = (x − D_θ(x,σ)) / σ` 具有半线性结构——线性项有解析闭式解，只需对网络输出项做多项式近似（指数加权积分）。DPM-Solver++ 利用该性质将网络输出的历史值用于高阶外推，在同等 NFE 下收敛阶数高于 Heun 的 2 阶。

**加速比**：10-12 NFE 达到 Heun-18 (36 NFE) 同等质量，约 3-3.6× 加速。

**质量影响**：脑 MRI 高频细节少，对离散化误差比自然图像更宽容。10 NFE 时 PSNR 下降通常 < 0.5 dB。5-8 NFE 仍可用，但肿瘤边界可能轻微模糊。

**代码修改思路**：

1. 在根目录 `model.py` 中新增 `sample_dpm_plus_plus()` 函数（约 120 行），核心逻辑：
   - 读取现有 `NoiseScheduleConfig` 中的 sigma_data、sigma_max、sigma_min、rho
   - 沿 EDM sigma 离散化序列 `t_steps` 做多步求解
   - 每步调用一次模型（1 NFE/步），用前两步的 denoised 输出做 2 阶外推
   - 遵从 EDM 的 preconditioning：`c_in = 1/√(σ²+σ_data²)`，`c_out = σ·σ_data / √(σ²+σ_data²)`，`c_skip = σ_data² / (σ²+σ_data²)`
   - 支持 CFG：当 `cfg_weight != 1.0` 时做 classifier-free guidance 外推
   - 支持 `snr_shift`
2. 在 `src/infer/diffusion_inference_utils.py` 的 `sample_tumour_diffusion_full()` 中新增 `dpm_plus_plus` 分支，dispatch 到 `model.py` 的新函数。`sample_tumour_diffusion_inpaint()` 同理。
3. 在 `src/infer/generate_from_label.py` 和 `src/infer/evaluate_generation.py` 的 `--sampling_method` 的 `choices` 列表中增加 `"dpm_plus_plus"`。

### 1.2 UniPC (Zhao et al. 2023)

**原理**：统一预测-校正（Unified Predictor-Corrector）框架。预测步骤利用历史多步模型输出做高阶外推；校正步骤用当前点再做一次额外模型调用以修正预测误差。通过调节预测/校正步的比例，可以在任意总 NFE 预算下最大化精度。

**加速比**：5-8 NFE 可达 Heun-18 质量，约 4.5-7× 加速；10 NFE 通常优于 Heun-18。

**质量影响**：预测-校正框架在极低步数时比纯多步预测更鲁棒，不易累积误差。8 NFE 质量通常看不出退化。5 NFE 以下可能出现轻微棋盘伪影（3D 卷积对此有一定抗性）。需要额外存储前 2-3 步的模型输出（约 16-24 MB 显存），可忽略。

**代码修改思路**：

1. 在根目录 `model.py` 中新增 `sample_unipc()` 函数（约 180 行），核心逻辑：
   - 读取 `NoiseScheduleConfig` 参数
   - 构建 EDM sigma 序列
   - 前三步使用 Euler 起步（积累历史 buffer）
   - 之后交替执行 predictor（用历史 buffer 做 2 或 3 阶外推）和 corrector（在当前点额外调用一次模型做误差修正）
   - 同样遵从 EDM preconditioning，支持 CFG 和 snr_shift
2. 与 DPM-Solver++ 相同的方式在 `diffusion_inference_utils.py` 中新增 `unipc` 分支
3. 两个入口脚本各加一行 `choices` 选项

### 1.3 关键适配说明

两个方法最初均针对 epsilon-prediction（预测噪声 ε）设计。本代码库的 EDM 模型是 data-prediction（直接预测干净 x₀，通过 `denoised = c_skip·x + c_out·F_θ`）。需要在 solver 实现中将 epsilon 空间的公式换算为 data 空间，数学上等价，需在实现时注意 sigma ↔ alpha_bar 换算。无需修改模型权重或重训。

## 二、其他加速方法

### 2.1 减少采样步数（针对当前 EDM 框架，1.1、1.2 方案可对应参考）

**原理**：EDM 的 sigma 离散化 `(σ_max^(1/ρ) + i/(N-1) · (σ_min^(1/ρ) − σ_max^(1/ρ)))^ρ` 在 ρ=7 时高噪声阶段步长大（那里细节不重要），低噪声阶段步长小（细节在此决定），对步数减少有天然的鲁棒性。

**加速比**：
- `--sampling_steps 12`（24 NFE）：~1.5× 加速
- `--sampling_steps 8`（16 NFE）：~2.25× 加速
- `--sampling_steps 5`（10 NFE）：~3.6× 加速

**质量影响**：12 步退化极微，8 步轻微退化，5 步可能出现细节丢失。建议从 18→12→8 递减测试，找到 PSNR/SSIM 拐点。

**使用方法**：直接改 CLI 参数 `--sampling_steps 12`，零代码改动。已支持。

### 2.2 FP16 / BF16 推理

**原理**：训练用 FP32 + AMP，纯推理时可全程使用半精度。FP16 将每个参数从 32 bit 压到 16 bit，Tensor Core 在半精度下吞吐更高；BF16 指数位与 FP32 相同（8 位），动态范围一致，数值稳定性更好。

**加速比**：约 1.5-2×。

**质量影响**：BF16 几乎无影响（动态范围与 FP32 一致）。FP16 在极端 sigma 值（噪声很大或很小时）可能出现数值下溢/上溢，但对 MRI 这种数据（值域有限）通常安全。

**代码修改思路**：

```python
# 加载模型后加一行
model = model.bfloat16()  # 或 model.half()
# 同步处理输入 tensor（在 diffusion_inference_utils.py 中）
label_tensor = label_tensor.bfloat16()  # 或 .half()
```

改动约 5 行，集中在 `diffusion_inference_utils.py` 的 `sample_tumour_diffusion_full()` 和 `sample_tumour_diffusion_inpaint()` 函数中，将输入 tensor 转为与模型一致的 dtype。

### 2.3 批量并行生成多病灶

**原理**：当前 `generate_from_label.py` 中每个病灶独立调用一次完整扩散采样（`sample_tumour_diffusion_full`），每次只处理一个 64³ volume。3D UNet 的 batch 维度利用率为 1，GPU SM 大量空闲。将同一患者的所有病灶的 label_cubes stack 成 `[N, C, 64, 64, 64]` 一次推理，GPU 利用率大幅提升。

**加速比**：接近 N_lesions×（受显存限制）。对于多病灶患者（N≥3），实测可达 2-4×。

**质量影响**：无。各病灶的初始噪声独立随机采样，生成结果互不影响。

**代码修改思路**：

修改 `generate_from_label.py` 的 per-lesion 循环：
1. 收集阶段：遍历 cc_list，将所有 `label_cubes` 预先提取、pad 到 `crop_size³`，收集到列表
2. Batch 推理：`label_batch = torch.stack(all_labels, dim=0)` 一次性送入 diffusion sampler，sampler 内部对 batch 维做并行前向
3. 拆分阶段：生成的 `[N, 1, S, S, S]` 按 batch 维拆开，分别做 content extraction 和 Gaussian blending

同时需修改 `sample_tumour_diffusion_full()` 和 `sample_edm()` / solver 函数，确保 sigma 序列是 `[batch_size]` 形状、初始噪声 `torch.randn(batch_size, *shape)` 已是按 batch 独立采样。当前代码已满足这些条件，batch 维度天然兼容。

改动约 50 行，集中在 `generate_from_label.py` 的主循环中。

### 2.4 INT8 模型量化

**原理**：将模型权重的浮点表示压缩为 8 位整数（INT8），减少推理时的显存占用和内存带宽压力。3D UNet 受内存带宽限制而非计算限制，量化后读写带宽减半可直接转化为延迟降低。

**加速比**：约 1.3-2×。3D 模型中速度提升主要来自带宽节省，纯计算提升有限。

**质量影响**：通常 PSNR 下降 < 0.5 dB。扩散模型对权重精度的敏感度低于分类模型（因为去噪过程有多步纠错机会）。建议先用 2.1+2.3 的组合，量化作为最后手段。

**代码修改思路**：

```python
# 方法 A: PyTorch 原生动态量化（最简单，但 3D Conv 支持有限）
model = torch.ao.quantization.quantize_dynamic(
    model, {torch.nn.Conv3d}, dtype=torch.qint8
)

# 方法 B: torchao INT8 权重量化（推荐，PyTorch >= 2.1）
from torchao.quantization import quantize_, int8_weight_only
quantize_(model, int8_weight_only())

# 方法 C: 导出为 TensorRT Engine（最大加速，但需额外工作）
# 需 ONNX → TensorRT 转换，支持 FP16 + INT8 混合精度
```

改动约 10 行，集中在 `diffusion_inference_utils.py` 的 `load_diffusion_model()` 函数中，加载权重后加一行量化调用。

## 总结

| 方法 | 加速比 | 代码改动 | 质量影响 | 优先级 |
|------|--------|----------|----------|--------|
| 1.1 DPM-Solver++ | ~3× | ~150 行 | < 0.5 dB | 高 |
| 1.2 UniPC | ~4.5× | ~200 行 | < 0.3 dB | 中（更复杂） |
| 2.1 减少采样步数 | 1.5-3.6× | 零 | 递减 | **立即试用** |
| 2.2 FP16/BF16 | 1.5-2× | ~5 行 | 极小 | **立即加** |
| 2.3 批量并行 | 2-4× | ~50 行 | 无 | **强烈推荐** |
| 2.4 INT8 量化 | 1.3-2× | ~10 行 | < 0.5 dB | 兜底 |

推荐优先级：**2.1 → 2.2 → 2.3 → 1.1 → 1.2 → 2.4**。
