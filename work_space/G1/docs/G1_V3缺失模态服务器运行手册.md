# G1 V3 缺失 T2W 填补服务器运行手册

## 1. 手册范围

本文档是 G1 最新 V3 缺失模态填补线的服务器操作依据。目标是用完整病例学习
`t1n + t1c + t2f -> t2w`，完成 validation 后，再给 265 个真正缺 T2W
的病例重建 T2W。

本文档不包含 G1 的 diffusion synthetic augmentation 线。两条线最终都可向
G2 提供数据，但训练目标、代码目录和输出目录不同，不得混用。

V3 唯一代码目录：

```text
/public/home/${USER}/projects/ECNU_EYU_data/work_space/G1/code/brats2025-latent-ensemble-synthesis-main-v3
```

旧 V2 VAE 作业已经取消。V3 不续跑 V2 checkpoint；只复用 V2 已经验证过的
原始 NIfTI 数据链接和固定 split，以免复制 40GB 数据。

## 2. 正确流程

```text
V3 smoke
  -> 接入已验证原始数据与固定 split
  -> patch VAE baseline / 微调 / 全 val 选择
  -> 人工检查 VAE
  -> 用被选 VAE 统一编码 1030 个完整病例
  -> EncDec 与 BBDM 并行训练
  -> 103 个 val 完整重建评估
  -> G2 配对影像/病灶 QC + 冻结 S2 teacher + 人工分层复核
  -> FINAL_GATE.json 明确 approve_stage6
  -> 265 个真缺 T2W 病例推理
  -> G2 QC
```

数据角色：

| 数据 | 数量 | 用途 | 是否有真实 T2W |
|---|---:|---|---|
| train | 823 | VAE、EncDec、BBDM 训练 | 有 |
| val | 103 | quick val、完整重建评估、调参 | 有 |
| locked test | 104 | 最终内部确认，平时不调参 | 有 |
| input_inference | 265 | 最终需要补 T2W 的目标病例 | 没有 |

`input_inference` 不是 test。它没有 ground-truth T2W，不能用于模型选择。

## 4. 第一批作业：smoke、数据接入、VAE

执行：

```bash
cd "${CODE_DIR}"
mkdir -p logs

SMOKE_JOB=$(sbatch --parsable slurm/00_smoke.slurm)
ADOPT_JOB=$(G1_V3_SOURCE_DATA_DIR="${SOURCE_DATA_DIR}" \
  sbatch --parsable --dependency=afterok:${SMOKE_JOB} \
  slurm/01_adopt_prepared_data.slurm)
VAE_JOB=$(sbatch --parsable --dependency=afterok:${ADOPT_JOB} \
  slurm/02_finetune_vae.slurm)

printf 'SMOKE=%s ADOPT=%s VAE=%s\n' "${SMOKE_JOB}" "${ADOPT_JOB}" "${VAE_JOB}"
```

依赖使用 `afterok`：前一步失败，后一步不会误跑。

监控：

```bash
squeue -u ${USER}
tail -f logs/g1v3_smoke_${SMOKE_JOB}.out
tail -f logs/g1v3_adopt_${ADOPT_JOB}.out
tail -f logs/g1v3_vae_${VAE_JOB}.out
```

### 4.1 阶段 0：smoke

输入：V3 源码、`segmamba`、预训练 MAISI VAE。

检查：

1. Python/PyTorch/MONAI/CUDA。
2. A100 是否真正可见。
3. VAE 权重是否与架构严格匹配。
4. 全部关键 Python 文件能否编译。
5. patch sampling 单元测试。
6. V3 EncDec/BBDM 在 batch=2 时的前向契约。

日志末尾必须出现：

```text
===== A100 smoke passed =====
```

### 4.2 阶段 1：接入数据

V3 的 `data/input` 和 `data/input_inference` 指向 V2 已验证 NIfTI 目录；
CSV、placement manifest、label report 被复制为 V3 独立文件。V3 后续生成的
latent、mask、VAE 权重和模型 checkpoint 全部独立，不回写 V2。

成功口径：

1. 1030 条完整病例 CSV。
2. 823 train、103 val、104 locked test。
3. 265 个 input_inference 病例。
4. input 与 input_inference 无病例重叠。
5. input_inference 中不存在 T2W。
6. `BraTS-MET-01094-002` 被排除。
7. `BraTS-MET-01184-002` 使用 corrected label。
8. 同一 `BraTS-MET-xxxxx` patient group 不跨 split。

### 4.3 阶段 2：VAE patch 微调

默认方案：

1. 全部 823 个 train 病例参与。
2. patch 为 `128×128×96`。
3. 四模态和 seg 使用完全相同裁剪。
4. 80% 均匀选择肿瘤连通域，20% 随机脑区。
5. 四个模态都训练共享 VAE。
6. BF16，关闭 activation checkpointing。
7. 最多 3 epoch。
8. 每个 epoch 固定 20 个 val 病例 quick validation。
9. early stopping patience=2。
10. 最后用全部 103 val 做完整体积比较。

VAE 输出目录：

```text
training/vae_finetuned/run_<jobid>/
```

必须存在：

```text
best_model.pt
baseline_metrics.csv
finetuned_metrics.csv
delta_metrics.csv
vae_selection.json
training_history.csv
finetune_config.json
quick_val_subjects.json
comparison_samples/*.png
```

`delta_metrics.csv` 必须为 412 行。自动选择条件：

- mean `delta_tumor_SSIM >= 0.03`；
- mean `delta_whole_SSIM >= -0.005`。

未达标时 `selected_weights` 会指向原始预训练 VAE。操作者还必须查看 5 张最差
病例图，确认没有错位、空白、明显模糊或肿瘤区域破坏，然后才能运行阶段 3。

## 5. 阶段 3：统一编码与辅助数据

VAE 验收后执行：

```bash
ENCODE_JOB=$(sbatch --parsable slurm/03_encode_and_prepare_aux.slurm)
echo "ENCODE_JOB=${ENCODE_JOB}"
```

该阶段会清理 V3 自己的旧 latent/mask/lesion-weight，然后执行：

1. 只用 `t1n/t1c/t2f + seg` 确定每例前景中心和自适应各向同性 spacing。
2. 将四模态和 seg 通过同一 affine-aware transform 映射到 `256×256×160`；前景和病灶视野外体素必须为 0。
3. 用 `vae_selection.json` 的 `selected_weights` 编码全部 1030 病例。
4. 每例写入 `data/latents/<case_id>/spatial_transform.json`，供 mask/weight 复用同一变换。
5. 生成 image-space 和 latent-space attention mask。
6. 生成 per-lesion V-weight mask。
7. 从 823 train 的真实 T2W latent 计算四通道权重。
8. 写入 `data/selected_vae.json`，冻结本轮 VAE 口径。

成功数量：4120 latent、1030 spatial transform、1030 attention mask、1030 lesion-weight mask。
任一病例失败，作业整体失败，不允许带缺口进入训练。

## 6. 阶段 4：并行训练两模型

```bash
ENDEC_JOB=$(TRAIN_TARGET=endec sbatch --parsable \
  --dependency=afterok:${ENCODE_JOB} slurm/04_train_models.slurm)
BBDM_JOB=$(TRAIN_TARGET=bbdm sbatch --parsable \
  --dependency=afterok:${ENCODE_JOB} slurm/04_train_models.slurm)
```

两个 job 可并行，每个 job 只申请一张 A100。默认：

| 参数 | EncDec | BBDM |
|---|---:|---:|
| batch size | 12 | 8 |
| max steps | 67000 | 201000 |
| seg-guided loss | 开 | 开 |
| learning rate | 1e-4 | 1e-4 |
| weight decay | 0.0 | 0.0 |
| BBDM s | - | 0.01 |
| checkpoint interval | 5000 | 5000 |

调参顺序：

1. 首先保持默认跑通基线。
2. BBDM 优先粗调 `s`，每个 `s` 必须独立训练并独立 val。
3. 只在确认过拟合后考虑 weight decay `1e-5` 到 `1e-4`。
4. 不在同一轮同时修改 `s` 与 weight decay，否则无法归因。

OOM 时先取消对应作业，只降低对应 batch。恢复 checkpoint 示例：

```bash
TRAIN_TARGET=bbdm \
G1_RESUME_CHECKPOINT=/absolute/path/model_50000.pt \
G1_MODEL_RUN_ID=bbdm_resume_50000 \
sbatch slurm/04_train_models.slurm
```

每个 run 会保存 `model_config.json`、`training_run.json`、TensorBoard 日志和
`check_points/model_<step>.pt`。推理选择最大数值 step，不按文件系统随机顺序。

## 7. 阶段 5：完整 val

两个训练作业都成功后：

```bash
EVAL_JOB=$(sbatch --parsable \
  --dependency=afterok:${ENDEC_JOB}:${BBDM_JOB} \
  slurm/05_evaluate_val.slurm)
```

默认在 103 个 val 病例上做 ensemble 重建，比较生成 T2W 与真实 T2W，输出
whole/brain SSIM、PSNR、MSE、MAE。任一病例失败或数量不是 103，作业失败。
评估与最终缺失模态推理使用同一空间处理：前景中心、自适应 spacing、
固定模型 shape，然后直接恢复到每例的原生 shape/affine。不允许在事后仅修 header 来伪装空间对齐。

输出：

```text
data/evaluation/val/run_<jobid>/metrics.csv
data/evaluation/val/run_<jobid>/spatial_audit.csv
data/evaluation/val/run_<jobid>/evaluation_run.json
data/evaluation/val/run_<jobid>/synthesized/*.nii.gz
data/evaluation/val/run_<jobid>/geometry_audit/geometry_audit.csv
data/evaluation/val/run_<jobid>/geometry_audit/geometry_audit.json
```

`evaluation_run.json` 固定记录被验证的 VAE、EncDec checkpoint、BBDM
checkpoint 和 `s`。`spatial_audit.csv` 必须正好 103 行、ID 与 `metrics.csv`
完全一致，且 `foreground_outside_voxel_count` 和 `lesion_outside_voxel_count`
全部为 0。`geometry_audit` 必须在不修改输出的审计模式下直接通过。

### 7.1 旧 checkpoint 的 14 例空间回归

修改空间处理后，先锁定上一次正式 run 的原 VAE/EncDec/BBDM checkpoint，
运行 11 个旧失败病例加 3 个正常对照：

```bash
cd "${CODE_DIR}"
SMOKE_EVAL_JOB=$(sbatch --parsable slurm/05b_evaluate_spatial_smoke.slurm)
echo "SMOKE_EVAL_JOB=${SMOKE_EVAL_JOB}"
```

该作业输出 `data/evaluation/val/spatial_smoke_<jobid>/`，不修改
`latest_run.txt`，也不覆盖正式 `eval_metrics_val.csv`。完成后对这 14 例运行
G2 paired QC，重点确认旧 11 例的空白/截断是否消失。该 smoke 只回答
“旧 checkpoint 在新空间流程下能否正常重建”，不能代替 103 例正式验收。

### 7.2 G2 正式验收与阶段 6 门

正式 103 例 Stage 5 完成后，在项目根目录并行提交两个 G2 作业：

```bash
cd "${PROJECT_ROOT}"
EVAL_JOB_ID="${EVAL_JOB%%;*}"
VAL_RUN_DIR="${CODE_DIR}/data/evaluation/val/run_${EVAL_JOB_ID}"

PAIR_QC_JOB=$(PROJECT_ROOT="${PROJECT_ROOT}" G1_V3_VAL_RUN_DIR="${VAL_RUN_DIR}" \
  sbatch --parsable work_space/G2/slurm/01_g2_v3_paired_quality.slurm)
TEACHER_JOB=$(PROJECT_ROOT="${PROJECT_ROOT}" G1_V3_VAL_RUN_DIR="${VAL_RUN_DIR}" \
  sbatch --parsable work_space/G2/slurm/02_g2_v3_s2_teacher.slurm)

printf 'PAIR_QC=%s TEACHER=%s\n' "${PAIR_QC_JOB}" "${TEACHER_JOB}"
```

paired QC 会硬验 `spatial_audit.csv`的病例数、ID 和视野外体素；teacher 固定使用
Dataset263 real-only S2 checkpoint。两个作业成功后，按 `review_index.csv`
完成 montage 分层复核，并在以下路径写入最终结论：

```text
work_space/G2/results/qc/v3_paired_validation/run_<stage5_jobid>/FINAL_GATE.json
```

`decision` 只能是 `approve_stage6`、`hold_for_review` 或 `reject_and_retune`；
`run_id` 必须与 Stage 5 目录名一致。

## 8. 阶段 6：265 个缺 T2W 病例推理

只有 paired QC、teacher 和人工复核都完成，且 `FINAL_GATE.json`
为 `approve_stage6` 后才执行：

```bash
cd "${CODE_DIR}"
VAL_APPROVED=1 \
G2_FINAL_GATE_JSON="${PROJECT_ROOT}/work_space/G2/results/qc/v3_paired_validation/run_<stage5_jobid>/FINAL_GATE.json" \
sbatch slurm/06_infer_missing_t2w.slurm
```

该作业读取阶段 5 记录的确切权重，不会切换到目录里更新的 checkpoint；默认不启用
额外 brain-mask 模型。脚本会硬验 gate 的 `decision` 和 `run_id`，
`hold_for_review`/`reject_and_retune` 不能通过。VAE、EncDec、BBDM 在作业内各加载一次，供 265 病例复用。

每个输出病例必须包含：

```text
<case_id>-t1n.nii.gz
<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

输出根目录：

```text
data/output/run_<jobid>/
```

必须正好 265 个病例、265 个生成 T2W。该 run 根目录交给 G2 QC；不要把
`input_inference` 原始目录或 val synthesized 目录误交给 G2。

## 9. 失败处理

查看状态：

```bash
squeue -u ${USER}
sacct -j <jobid> --format=JobID,JobName,State,Elapsed,ExitCode,MaxRSS
```

取消：

```bash
scancel <jobid>
```

处理原则：

1. `00` 失败：先修环境或模型接口，不继续。
2. `01` 数量不符：检查 source data，不改 expected count 绕过。
3. `02` OOM：只先将 `VAE_BATCH_SIZE=1`。
4. `03` 有病例失败：修数据/路径后整阶段重跑。
5. `04` OOM：降低该模型 batch；其他超参数不一起改。
6. `05` 有病例失败、spatial/geometry audit 不通过：禁止进入 G2/06。
7. G2 paired/teacher/人工任一未完成或 gate 非 `approve_stage6`：禁止进入 06。
8. `06` 输出不是 265：禁止交 G2 completion intake。
