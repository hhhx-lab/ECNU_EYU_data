# BraTS 2026 脑转移瘤 — 扩散模型改造分析

## 1. 竞赛新规

### 1.1 BraTS 2026 四标签体系

| 标签 | 名称 | 定义 |
|---|---|---|
| Label 1 | NETC (Non-enhancing tumor core) | 无对比增强的肿瘤核心部分，由增强肿瘤包围，是手术切除的主要目标 |
| Label 2 | SNFH (Surrounding non-enhancing FLAIR hyperintensity) | 瘤周水肿和浸润组织，表现为 T2 FLAIR 高信号，不包括缺血白质改变等非肿瘤信号 |
| Label 3 | ET (Enhancing Tumor) | 增强肿瘤，T1c 上有明显对比增强，不包括相邻血管、出血或固有 T1 高信号 |
| Label 4 | RC (Resection Cavity) | 切除腔，仅存在于术后病例 |

### 1.2 检测排行榜 (Detection Leaderboard)

2026 年新增检测排行榜，关注 <**27mm³** 的小病灶，要求模型能对微小病灶进行独立计数和量化。

## 2. 转移瘤 vs 胶质瘤：任务差异

| | 胶质瘤（原代码设计场景） | 转移瘤（新任务） |
|---|---|---|
| 病灶数量 | 通常 1 个 | **多发，可能几十个** |
| 病灶大小 | 较大，30~96 体素 | **大量 <27mm³ 的小病灶** |
| 空间分布 | 集中，bbox 裁剪可行 | **散布全脑，bbox 策略漏小病灶** |
| 肿瘤形态 | 不规则浸润 | 多为类圆形、边界相对清晰 |
| 标签通道数 | 4 类 = 4 通道 | 4 类 = 4 通道（一致） |

## 3. 现行代码的障碍

### 3.1 硬障碍一：多发病灶

当前 `csv_creator.py` 每个患者只记一个肿瘤中心点和 bbox。多发转移瘤散布全脑，只取一个中心点会丢掉其余所有病灶。

**改造方案**：CSV 创建阶段对每个患者的 label 做连通域分析，每个连通域独立成行，记录各自的中心点和 bbox。训练时 DataLoader 随机采样不同病灶的 crop。生成时检测所有连通域逐个成图后拼回全脑。

### 3.2 硬障碍二：极小病灶（<27mm³）

27mm³ ≈ 3³ 体素，在 96³ 的 crop 里占比不到万分之四。模型去噪时信号几乎不可见，训练容易退化，生成结果中小病灶直接消失。

## 4. Crop 策略分析与选择

### 4.1 候选尺寸比较

| 考量 | 48³ | **64³** | 96³（现行） |
|---|---|---|---|
| SwinUNETR 最深特征图 | 3³，自注意力退化 | **4³（64 token），可用下限** | 6³，安全 |
| 小病灶（5mm³）在 crop 中占比 | 0.11% | 0.05% | 0.01% |
| 能装下多大病灶（不截断） | ~24mm | **~32mm** | ~48mm |
| 单 crop 计算量 vs 96³ | 1/8 | **1/3.4** | 基准 |
| 周围组织 context | 不足 | 基本足够 | 充裕 |

### 4.2 结论：统一 64³

**48³ 排除**：SwinUNETR 四层下采样后特征图仅 3³（27 个 token），自注意力退化为无意义的密集运算，Transformer 优势消失。且 24mm 以上的病灶会截断。

**64³ 入选**：最深特征图 4³（64 token），维持 SwinUNETR 有效性的下限。绝大多数转移瘤（<32mm）能完整装入。比 96³ 快 3.4 倍。

**32³ 排除**：装不下中等以上病灶（>16mm 截断），且最深特征图仅 2³（8 token）完全无自注意力价值。

### 4.3 大病灶兼容

极少数 >32mm 病灶：crop bbox 后立方插值缩放到 64³ 送入模型，生成后上采样贴回。训练时也做同样缩放以保证一致性。

## 5. 训练策略

### 5.1 数据准备

- CSV 创建时对 label 做连通域分析，每个连通域独立成行
- 相邻病灶（间距 <16 体素）合并为一个 crop
- 每个 row 记录：病灶 ID、中心点、bbox、尺寸、所属患者

### 5.2 加权采样

训练时小病灶（<10mm³）被抽中概率 ×3~5，防止被大病灶的 loss 主导。

### 5.3 计算开销

每步仍是 1 个 64³ crop。CSV 行数变多但单步计算量不变（且比 96³ 小 3.4 倍）。

训练开销 = 现行方案的 **30%**。同样的 GPU 时间可跑 500k 步而非 150k 步。

---

## 6. 推理策略

### 6.1 连通域检测

对每个患者的 label 做连通域分析，按病灶大小分路处理。

| 病灶尺寸 | 处理方式 |
|---|---|
| <10mm³ | 以 bbox 为中心 crop → pad 到 64³ → 生成 → 贴回原位置 |
| 10~32mm³ | 同上，直接装入 64³，不缩放 |
| >32mm³（极少） | 缩放 bbox 区域到 64³ → 生成 → 上采样回 → 贴回 |

### 6.2 合并策略

相邻病灶（bbox 中心间距 <16 体素）合并入同一个 64³ crop，减少冗余生成和接缝。

### 6.3 计算开销对比

| | 现行（96³ 单 crop） | 提案（64³ 多 crop） |
|---|---|---|
| 单 crop 耗时 | T | 0.3T |
| 每例 crop 数 | 1 | 加权平均 8~12 |
| 每例总耗时 | T | 2.5T~3.6T |
| 四模态/例（估） | ~80s | ~3~5 分钟 |

训练便宜了（×0.3），推理贵了（×3），但这是多发病灶 + 小病灶检测必须付出的代价——现行方案根本看不见小病灶。

## 8. 关键注意事项

1. SwinUNETR 输入必须是 16 的倍数（4 级下采样，stride ¹⁶）：32/48/64/80/96 都合法
2. `plan_network_params()` 根据 `input_size` 自动计算通道数和下采样级数，尺寸改变后模型自动适配
3. checkpoint 与 crop 尺寸绑定（feature map 维度不同），改尺寸后需从头训练
4. 全脑拼接多个 crop 时有边缘接缝问题，需 overlap sliding window + Gaussian blending
5. 四类标签语义（NETC/SNFH/ET/RC）不变，现有 4 通道 label 转换逻辑无需修改
6. 多卡训练时需确保同一患者的不同病灶不跨卡同时出现在一个 batch（避免梯度冲突），或显式拆分
