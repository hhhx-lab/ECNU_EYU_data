# S1/S2 分割模型总结说明

更新日期：2026-07-08

本文用于解释 `work_space/S1` 和 `work_space/S2` 两个分割模型部分目前分别做什么、输入输出是什么、如何和 G1/G2 配合、怎么训练与调参，以及当前结果进度。本文只总结当前仓库里的真实代码和文档状态，不把尚未跑出的训练结果写成已完成。

## 1. 总体定位

S1 和 S2 同属分割模型小组，最终目标是把真实数据和 G1/G2 提供的合成数据转化为可量化的分割模型结果，用来回答两个问题：

1. 真实数据基线能做到什么水平。
2. 加入 G1 生成、G2 QC 通过的 synthetic data 后，分割性能是否提高，尤其是否改善 RC、ET、TC、WT 和小病灶指标。

当前两条线的定位不同：

| 模块 | 当前代码位置 | 技术路线 | 作用 | 当前成熟度 |
| --- | --- | --- | --- | --- |
| S1 | `work_space/S1/brats2026_multitask_S1_v2/repository` | MONAI 3D UNet 多任务模型 | 同时预测 tumor subregions 和 RC，作为探索性多任务方案 | 已有代码框架，暂无训练结果 |
| S2 | `work_space/S2/BraTS2026_S2_RC_v1.0/repository` | nnU-Net v2 + 自定义 trainer | 作为主基线和 RC 优化线，更接近正式训练流程 | 代码更接近可训练主线，暂无训练结果 |

简单说：

- S2 应优先作为主力 baseline 跑通，因为它基于 nnU-Net v2，和官方分割任务更贴近。
- S1 可作为多任务探索和辅助对照，重点看 RC head 是否能带来额外收益。

## 2. 和 G1/G2 的协作关系

四个模块之间的数据流应该按下面顺序走：

```text
原始 Task1 数据
  |
  v
G2 真实数据 QC、manifest、固定 train/val/test split
  |
  +--> S1/S2 real-only baseline 训练
  |
  +--> G1 T2W completion 或 G1 diffusion augmentation
          |
          v
      G2 synthetic intake + QC + accepted/rejected
          |
          v
      G2 物化 real+synth 训练集
          |
          v
      S1/S2 real+synth 消融训练
          |
          v
      G2 解析指标、汇总 ablation report
```

### 2.1 G1 给 S1/S2 提供什么

G1 目前有两类输出，不能混淆：

1. T2W completion
   - 输入：缺失或 fake/broken T2W 的病例，通常含 `t1n/t1c/t2f/seg`，不含可用 `t2w`。
   - 输出：补出的 `<case_id>-t2w.nii.gz`。
   - 用途：修复真实病例中的缺失/异常 T2W。它默认不是新增 synthetic case，而是补齐原病例通道。

2. Diffusion augmentation
   - 输入：完整真实病例的 `seg` 或 lesion/ROI 条件。
   - 输出：synthetic `t1c/t1n/t2w/t2f/seg`。
   - 用途：作为额外 synthetic cases 追加到训练集，用于 real+synth augmentation。

### 2.2 G2 给 S1/S2 提供什么

G2 的职责是把 G1 的 raw output 变成可训练、可追溯、可审计的数据资产。

S1/S2 不应该直接吃 G1 raw output，而应该吃 G2 产物：

- 真实数据 manifest：`work_space/G2/results/manifests/real_train_manifest.csv`
- 固定划分：`work_space/G2/results/splits/splits_final_train_val_test.json`
- nnU-Net real-only 入口：`work_space/G2/results/nnunet_raw/Dataset260_BraTS2026_MET_RealOnly/`
- synthetic accepted/rejected manifest：正式 G1 run 后由 G2 生成
- real+synth nnU-Net 物化入口：正式 G1 run 后由 G2 生成
- QC 报告和 ablation 模板：`work_space/G2/results/qc/`、`work_space/G2/results/reports/`

### 2.3 当前统一通道顺序

S1/S2 已统一为 G2 物化数据和 nnU-Net `dataset.json` 默认顺序：

```text
0000 = t1n
0001 = t1c
0002 = t2w
0003 = t2f
```

具体体现：

- S1 loader 和 S1 inference 读取顺序是 `t1n, t1c, t2w, t2f`。
- S2 `01_convert_to_nnunet.py` 写出顺序是 `0000=t1n, 0001=t1c, 0002=t2w, 0003=t2f`。
- S2 `dataset.json` 的 `channel_names` 是 `0=T1N, 1=T1C, 2=T2W, 3=T2F`。

后续 G2 物化 real-only 和 real+synth 数据时必须沿用这一顺序。不要再使用旧顺序 `t1c,t1n,t2f,t2w`。

### 2.4 当前裸 real-only baseline 定义

这里的“裸的 real-only”不是把所有原始病例不加筛选地混在一起跑，而是指：

```text
G2 final QC pass 的真实原始数据
+ corrected label overlay 后的有效 seg
+ G2 固定 train/val/test split
+ 统一 channel order: t1n,t1c,t2w,t2f
+ 不使用 G1 T2W completion 输出
+ 不使用 G1 diffusion synthetic 输出
```

当前固定 split 口径：

| split | 数量 | 用途 |
|---|---:|---|
| train | 829 | 参与训练 |
| val | 207 | 训练过程中的固定内部验证 |
| internal locked test | 259 | 暂不参与训练、预处理、调参，只保留清单 |

因此 S1/S2 第一轮服务器任务应先跑 **clean real-only baseline**。G1 目前只拉回 CSV 指标和数据摆放记录，没有拉回 `.nii.gz` 生成结果，所以暂时不能做 real+synth。

## 3. S1 说明

### 3.1 S1 的作用

S1 是一个 MONAI 多任务模型框架，目标是在一个模型里同时完成两个任务：

1. tumor subregion segmentation
   - 输出 4 类：background、NETC、SNFH、ET。
2. RC segmentation
   - 输出 2 类：background、RC。

设计思路是共享一个 3D UNet backbone，再接两个输出 head：

- tumor head：预测 tumor subregions。
- RC head：预测 recurrence component。

这个方案的价值在于探索 RC 是否应该作为单独任务显式学习，而不是只作为普通多类分割中的一个类别。

并且必须检查 label 合法范围只包含 `0,1,2,3,4`。

### 3.7 S1 调参重点

优先调参顺序：

1. `patch_size`
   - 当前是 `96,96,96`。
   - 显存不足先降 batch size，不要轻易把 patch 降太小。

2. `batch_size`
   - 当前 full config 是 2。
   - 如果 24G GPU OOM，先试 1。

3. `lr`
   - 当前是 `3e-4`。
   - 如果 loss 震荡或 NaN，先降到 `1e-4`。

4. RC loss 权重或不确定性权重策略
   - 当前 `MultiTaskLoss` 使用 uncertainty weighting。
   - 如果 RC dice 长期为 0，可考虑显式给 RC loss 加权。

5. tumor/RC 融合策略
   - S1 的 RC 是单独 head，最后如何覆盖 tumor_pred 会影响最终 label map。
   - 推荐先使用 `rc_pred==1` 覆盖为 4，再做 connected component 和小病灶检查。

## 4. S2 说明

### 4.1 S2 的作用

S2 是当前更接近主线 baseline 的实现，基于 nnU-Net v2。它的目标是：

1. 把 BraTS-MET 数据转换成 nnU-Net raw dataset。
2. 使用固定 train/val split。
3. 使用自定义 trainer 强化 RC 类别学习。
4. 训练 real-only baseline。
5. 后续训练 real+synth ablation，对比 synthetic data 是否有效。

### 4.2 S2 当前代码结构

- 实际推理入口是 `infer.sh`。

### 4.3 S2 输入

S2 real-only 的影像来源仍是原始 BraTS-MET NIfTI 数据，但训练入口必须经过 G2 的 real-only mapping 和固定 split。每个被纳入 train/val 的病例至少需要：

```text

<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

S2 会转换为 nnU-Net raw 格式：


当前 S2 real-only 的默认输出位置是：


### 4.7 S2 自定义 trainer 做了什么

核心文件：

```text
work_space/S2/BraTS2026_S2_RC_v1.0/repository/custom_nnunet/nnUNetTrainerBraTS2026RC.py
```

主要改动：

1. 固定训练轮数
   - `num_epochs = 1000`

2. RC-aware CE 权重
   - CE weight = `[1.0, 1.0, 1.0, 1.0, 3.0]`
   - RC 类别权重为 3。

3. 固定 split
   - `train_full.txt`
   - `val_full.txt`

4. 保留 nnU-Net v2 原始训练、验证、deep supervision、augmentation 和推理框架。

### 4.8 S2 调参重点

优先调参顺序：

1. RC CE weight
   - 当前是 3。
   - 可试：3、5、10。
   - 如果 RC recall 太低，提高权重。
   - 如果 false positive 太多，降低权重或加后处理。

2. patch size / batch size
   - 由 nnU-Net plan 决定。
   - 如果显存不足，优先让 nnU-Net 自动 plan，而不是手工硬改。

3. epoch 数
   - 当前 1000。
   - 如果过拟合，观察 validation Dice/NSD 后早停或选 best checkpoint。

4. foreground oversampling
   - 当前 `oversample_foreground_percent = 0.33`。
   - 小病灶漏检多时，可考虑提高。

5. post-processing
   - 对 tiny false positive 可用连通域过滤。
   - 但不能一刀切删除小病灶，因为官方榜单包含 small instance 指标，小病灶是真正评分重点。

## 5. real-only 与 real+synth 实验设计

S1/S2 后续必须至少跑两组实验：

| 实验 | 训练数据 | 验证数据 | 目的 |
| --- | --- | --- | --- |
| real-only baseline | G2 final QC pass 的真实 train | 固定 real val | 得到无 synthetic 的基准 |
| real+synth smoke | real train + 少量 accepted synthetic | 固定 real val | 检查 synthetic 是否不会拉坏性能 |
| real+synth main | real train + 策略比例 accepted synthetic | 固定 real val | 正式评估 G1/G2 synthetic augmentation 是否有效 |
| final internal test | 最优方案 | 固定 internal test | 只做最终内部评估，不调参 |

不能用 internal test 调参。官方 validation/pseudo-test 也不能用于模型选择。

## 6. 结果应该怎么汇总

   - synthetic run id，如果使用 synthetic。

2. checkpoint 信息
   - best checkpoint。
   - final checkpoint。
   - 训练轮数。
   - 是否 resume。

3. 验证集预测结果
   - 每个 case 的 predicted segmentation。
   - 原始 label。
   - inference 命令。

4. 指标表
   - Dice。
   - NSD。
   - lesion-wise DSC/NSD。
   - small instance TP/FN/FP/F1。
   - ET、TC、WT、RC 分别统计。

5. 消融结论
   - real-only vs real+synth。
   - 是否提升 RC。
   - 是否提升小病灶。
   - 是否拉低 ET/TC/WT。
   - 如果只对某类病灶有效，结论必须限制使用范围。

## 8. 一句话结论

S2 是当前优先跑通的 nnU-Net v2 主基线；S1 是多任务 RC 探索线；S4 可以后置 smoke test，但严格对比前还要接入 G2 固定 split。G1 负责生成补全或 synthetic 数据，G2 负责 QC、manifest、物化和指标汇总。S1/S2 不能直接吃 G1 raw output，必须吃 G2 放行后的 real-only 或 real+synth 数据入口。当前仓库已有 S1/S2 real-only Slurm 入口，通道顺序已统一为 `t1n,t1c,t2w,t2f`，主要路径已改成环境变量/参数可配置，但还没有提交可证明模型效果的训练结果和官方风格指标。
