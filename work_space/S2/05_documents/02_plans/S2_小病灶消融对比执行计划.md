# BraTS 2026 S2 小病灶消融对比执行计划

## 1. 目的与结论

本计划用于在不混入在线 Diffusion 增强、官方 179 例推理或提交的前提下，选择后续
S2 Diffusion 增强应使用的 nnU-Net 基座。目标不是根据机制假设直接确定方案，而是在
固定 Dataset264 和固定 103 例验证集上完成可解释的消融对比。

**最终状态（2026-07-24）**：首轮比较和正式病灶级评估已完成。E
（`nnUNetTrainerBraTS2026RCFocalCompletionFineTune`，Focal `gamma=2.0`）冻结为
小病灶方向的后续基座；B 保留为总体分割的保守基线。A-1 和 A-1+E 不作为后续基座。
完整数值、风险复核和 checkpoint SHA256 见
`results/s2_small_lesion_ablation_20260721/final_comparison_20260724.md` 与
`checkpoint_selection.json`。

首轮不直接叠加全部三处改动。固定比较原版 B、A-1、E 和 A-1+E；D 仅作为首轮后
有证据的二阶段候选。A-2 暂不进入首轮。

```text
Dataset264 固定缓存
        |
        +--> B: 原版已完成 baseline
        +--> C-A1: 仅降低一次下采样
        +--> C-E: 仅 Focal CE
        +--> C-A1E: A-1 + Focal CE
                         |
                    同一固定 103 例
                         |
               官方兼容评估 + 分层风险复核
                         |
        冻结 E 为小病灶后续基座；B 保留为总体基线
```

## 2. 范围与禁止项

本计划只覆盖 S2 segmentation 的基座选择，固定使用
`Dataset264_BraTS2026_MET_Completion`。

- 不启动在线 Diffusion 训练。
- 不对官方 179 例推理，不打包、不提交。
- 不删除原版 B、既有 checkpoint、Dataset264 缓存或 G1/G2 产物。
- 不将训练过程中的 nnU-Net `summary.json` 当作最终官方兼容指标。
- 不把 A-1/A-2 同时视为可叠加改动，它们是同一架构位置的互斥选择。

## 3. 数据与不变量

所有候选都必须满足以下不变量；任一不满足则该候选无评估资格。

| 项目 | 固定值或要求 |
|---|---|
| 数据集 | `Dataset264_BraTS2026_MET_Completion` |
| 通道顺序 | `0000=t1n, 0001=t1c, 0002=t2w, 0003=t2f` |
| 数据物化 | `included_cases=1242`，`completion_paths_overridden=212` |
| 划分 | train/val/locked test = `1035/103/104` |
| 验证集 | 同一固定 103 例，不调参后换集 |
| 预处理 | Dataset263 checkpoint 对应 plans，`numTraining=1138` |
| 训练轮次 | 200 epochs |
| 初始学习率 | 0.001 |
| 保存频率 | 每 25 epochs |
| Focal 参数 | `gamma=2.0`，RC class weight 保持 `3.0` |
| 评估 | BraTS_evaluation mets 官方兼容口径 |

缓存必须在所有候选训练完成前保留。`/public` 可用空间始终高于 1 TiB；低于阈值时
停止启动新任务并优先保护 checkpoint、验证预测和审计文件。

## 4. 首轮候选矩阵

| 编号 | Trainer | 改动 | warm-start | 首轮目的 |
|---|---|---|---|---|
| B | `nnUNetTrainerBraTS2026RCCompletionFineTune` | 原版 RC-aware Dice+CE | 已完成的完整 warm-start | 比较基准 |
| C-A1 | `nnUNetTrainerBraTS2026RCA1CompletionFineTune` | 5 stage、4 次各向同性下采样 | 同名同形状参数部分加载 | 单独验证空间分辨率收益 |
| C-E | `nnUNetTrainerBraTS2026RCFocalCompletionFineTune` | Dice + Focal CE | 原版完整 warm-start | 单独验证难体素再加权 |
| C-A1E | `nnUNetTrainerBraTS2026RCA1FocalCompletionFineTune` | A-1 + Dice + Focal CE | 同名同形状参数部分加载 | 验证两者是否互补 |

### 4.1 A-1

A-1 将原版 6 stage/5 次下采样改为 5 stage/4 次各向同性下采样。其预期收益是让极小
病灶在 bottleneck 保留更多空间表达；代价是深层感受野略小。

该改动改变网络拓扑，不能使用 nnU-Net 默认的严格预训练加载器。A-1 候选必须生成
`partial_warmstart_audit.json`，记录 checkpoint SHA256、实际加载参数、形状不匹配参数和
未加载 segmentation head。日志必须包含 `A1_PARTIAL_WARMSTART_PASS`。

### 4.2 E: Focal CE

E 只替换 CE 分支，不替换 Dice 分支。`gamma=2.0`，保留原 RC 类权重 `[1,1,1,1,3]`、
ignore-label 语义和深度监督。

这避免已被正确学习的大面积体素长期主导 CE 梯度，同时仍让 Dice 维护整体轮廓。Focal
不等同于“小病灶损失”，因此必须通过小病灶分层结果验证，不得以整体 loss 下降代替验证。

### 4.3 D: 延后到二阶段

D 的科学方向可以保留，但 README 中的实现描述不能直接执行。当前
`_get_deep_supervision_scales` 返回的是标签缩放尺度，不是 loss 权重；直接把
`[0.40, 0.30, 0.15, 0.10, 0.05]` 返回给该方法会破坏监督分辨率。

若首轮最优模型仍有明确小病灶瓶颈，D 必须在 `_build_loss` 中设置
`DeepSupervisionWrapper` 的权重，并与实际 decoder 输出数量严格一致：原版 6-stage 为
5 个输出，A-1 5-stage 为 4 个输出。D 只能作为“首轮最佳候选 + 正确 D”的单独二阶段
对照，不能回写或覆盖首轮结果。

### 4.4 A-2: 暂不进入首轮

A-2 与 A-1 都是第五个 stage 的架构选择，不能同一训练中并用。A-2 只在以下情形追加：
A-1 在大病灶或特定物理轴上出现可复现退化，且该退化不能由训练不稳定、warm-start
加载覆盖率或数据异常解释。

## 5. 训练前 Gate

训练作业只能依赖通过的缓存验收任务。验收必须检查：

1. `included_cases=1242` 与 `completion_paths_overridden=212`。
2. split 精确为 `1035/103/104`，无重复、无 train/val 重叠。
3. `imagesTr`、`labelsTr`、固定 split 和预处理 cache 的 ID 集完全相同。
4. cache 为有效 b2nd 格式，1138 个病例均有 data/seg companion。
5. Dataset264 plans 与 Dataset263 baseline checkpoint 的 plans 契约一致，仅
   `dataset_name` 替换为 Dataset264。
6. `/public` 可用空间大于 1 TiB。

成功时记录 `S2_COMPLETION_PREP_PASS.ok`；失败时不释放任一候选训练。

## 6. 训练健康 Gate

每个候选启动后需要同时核验：

- 实际 Slurm 作业、`nnUNetv2_train` 进程和 GPU PID 三者一致。
- GPU 显存至少 30 GiB。
- trainer 名称与候选矩阵一致，输出目录使用 trainer 名称隔离。
- epoch 连续增长，训练/验证 loss 有限，没有 NaN、Inf、OOM、Traceback 或异常退出。
- checkpoint 按 25 epoch 产生，`checkpoint_final.pth`、103 个 validation 预测和
  `validation/summary.json` 都存在后才可标记训练完成。
- A-1/A-1E 存在 `A1_PARTIAL_WARMSTART_PASS` 和 `partial_warmstart_audit.json`。
- E/A-1E 日志和配置确认 `S2_FOCAL_GAMMA=2.0` 与 RC 权重 `3.0`。

单纯 PID 存活不构成健康证据。日志、checkpoint mtime、GPU 活动和 epoch 必须至少两项
持续增长；长时间没有进展时先诊断，不直接重启或删除产物。

## 7. 统一评估与人工复核

所有候选完成后，先将每个模型的 103 个 validation 预测映射回同一 source ID，再用
BraTS_evaluation mets 官方兼容配置评估。评估输入、reference、版本、命令、预测
manifest 和输出 SHA256 必须归档。

比较必须至少包含：

| 层面 | 必须比较的内容 |
|---|---|
| 总体 | 官方兼容主指标、Dice、HD95 或对应 mets 输出 |
| 病灶类别 | RC 与其他标签的分项表现 |
| 尺寸分层 | tiny/small、常规、大病灶 |
| 风险 | 漏检小病灶、RC 退化、假阳性、边界异常 |
| 稳定性 | 训练是否出现不稳定、异常 warm-start 覆盖率或显存问题 |

人工复核优先级为：低分病例、RC、tiny lesion、large/tiled、自动告警病例。总体均值提升
不能覆盖严重的小病灶漏检或 RC 风险。

## 8. 决策规则

选择顺序如下：

1. 先排除没有通过训练、产物完整性、统一评估或人工风险复核的候选。
2. 在合格候选中优先看官方兼容主指标和小病灶分层是否同步改善。
3. 若整体略升但 tiny/RC 出现实质退化，保留为非最终候选。
4. A-1+E 只有在相对其单项均有可验证净收益时才作为“组合优于单项”的结论；否则选择
   贡献更清楚、风险更低的单项。
5. 若全部候选都没有净收益，保留原版 B，不为了使用改动而替换基座。
6. 仅当首轮最佳模型仍有明确小病灶不足时，进入正确实现的 D 二阶段；二阶段仍使用同一
   固定 103 例和同一评估口径。

最终选择写入 `checkpoint_selection.json`，其中必须包含候选名、checkpoint 路径、
SHA256、训练数据契约、评估结果摘要、人工复核结论和选择理由。

## 11. 对后续 Diffusion 的边界

本计划冻结的 E 仅是后续 S2 online Diffusion 候选的基座。G2 gate 已批准的 Diffusion
只可在训练 patch 层按固定概率生成和插入肿瘤；未成功插入必须保持样本原样。
validation、test、官方推理和官方提交阶段均不得调用 Diffusion。

基座选择已经冻结，但在 Route A-F 的独立离线 Gate、适配器和用户明确授权完成前，仍不得
启动在线 Diffusion。

## 12. 最终冻结结论

| 用途 | 冻结选择 | 依据 |
|---|---|---|
| S2 小病灶后续训练基座 | **E / Focal CE** | WT small-instance F1 `0.333083`；RC DSC/NSD/F1 均高于 B，RC FP 从 `0.679612` 降至 `0.038835` |
| Dataset264 总体分割保守对照 | **B / 原版 RC-aware Dice+CE** | WT lesionwise DSC `0.593539`、NSD `0.593146`、all-instance F1 `0.723753`，均为四个 Dataset264 候选最高 |
| 不采用 | A-1 | WT DSC/NSD/F1/small-instance F1 退化且 FP 增加；RC 收益不够平衡 |
| 不采用 | A-1+E | 虽 WT small-instance F1 最高，但 WT 主指标退化、WT FP 最高，RC F1/FP 不及 E |
| 二阶段候选 | E + 正确 Deep Supervision D | E 仍有 RC/小病灶瓶颈；只设计，不启动 |

后续任何 S2 合成增强路线必须显式记录 `base_candidate=E`，不得从 B、A-1 或 A-1+E
重新派生。正式评估只有固定内部 103 例结果，不等同于官方 179 例提交结果。
