# S2 服务器运行手册

## 1. 默认正式口径

S2 默认运行当前 G2 patient-group real-only fixed split，不运行交叉验证：

```text
experiment mode       current
train                 823
validation            103
internal locked test  104
dataset               Dataset263_BraTS2026_MET_RealOnly_Current
nnU-Net CLI key       0
```

`fold_0/` 只是 nnU-Net 要求的 API/结果目录键，不代表五折。脚本拒绝 folds 1-4 和 Slurm Array。

历史 Dataset260 模型的 `828/207/259` 划分只用于历史复核，不能作为当前 real-only vs real+synth paired baseline。历史模式见第 11 节。

本手册中的两个 validation 必须严格区分：

1. **内部 validation：103 例，有真值。**用于训练监控、模型选择和本地指标分析。
2. **官方 validation：179 例，无公开真值。**只在模型确定后生成预测并提交 Synapse。

`leaderboard_metrics.csv` 和内部 103 例预测不是官方提交文件；Synapse 只接收官方 179 例预测压缩包。

### 1.1 ECNU completion-only 当前路线

G1 V3 缺失 T2W 补全线已产生 265 例，G2 技术 QC 通过 265/265。Completion-only S2 仅将其中属于 train 的 212 例加入训练：

```text
train                 823 real + 212 completion = 1035
validation            103 real, 保持不变
internal locked test  104 real, 保持不变
dataset               Dataset264_BraTS2026_MET_Completion
trainer               nnUNetTrainerBraTS2026RCCompletionFineTune
warm start             Dataset263 real-only checkpoint_final.pth
```

这一路线是“补全数据增量微调”，不是尚未收口的 G1 Diffusion 在线增强。它可以与云端四模态 Diffusion 同时运行。

ECNU `/public` 已使用 99%，Dataset264 的 raw 链接目录、preprocessed 缓存、训练 results 和最终 checkpoint 统一放在：

```text
/hpc_stor/data/$USER/ECNU_EYU_data/work_space/S2/data/ecnu_completion/
  nnUNet_raw/
  nnUNet_preprocessed/
  nnUNet_results/
  published/
```

首次运行前先检查：

```bash
test -d "/hpc_stor/data/${USER}" && test -w "/hpc_stor/data/${USER}"
```

当前账号若没有该目录或写权限，必须请集群管理员创建用户专属目录。管理员可参考：

```bash
mkdir -p /hpc_stor/data/zqchen
chown zqchen:users /hpc_stor/data/zqchen
chmod 700 /hpc_stor/data/zqchen
```

操作者不得自行使用 `sudo`。默认情况下也不得把 `S2_STORAGE_ROOT` 改回 `/public`；只有下述显式 emergency 模式例外。Slurm 已加入硬检查，不满足时会在预处理前失败。

赛期紧急时可启用受控的 `/public` emergency 模式。它不是默认回退，必须同时满足：

1. `S2_ALLOW_PUBLIC_EMERGENCY=1`。
2. 存储路径精确等于 `${PROJECT_ROOT}/work_space/S2/data/ecnu_completion_emergency`。
3. `/public` 剩余空间不少于 `1024GiB`。
4. 任务运行期间每 300 秒复查；低于阈值时自动取消 Slurm 任务。

紧急提交命令：

```bash
cd /public/home/${USER}/projects/ECNU_EYU_data
EMERGENCY_ROOT="${PWD}/work_space/S2/data/ecnu_completion_emergency"
COMMON_EXPORT="S2_ALLOW_PUBLIC_EMERGENCY=1,S2_PUBLIC_MIN_FREE_GIB=1024,S2_PUBLIC_CHECK_INTERVAL_SECONDS=300,S2_CLEAN_PUBLIC_AFTER_SUCCESS=1,S2_STORAGE_ROOT=${EMERGENCY_ROOT}"

PREP_JOB=$(sbatch --parsable \
  --export=ALL,${COMMON_EXPORT} \
  work_space/S2/slurm/01_prepare_completion_ecnu.slurm)

TRAIN_JOB=$(sbatch --parsable \
  --dependency=afterok:${PREP_JOB} \
  --export=ALL,${COMMON_EXPORT} \
  work_space/S2/slurm/02_train_completion_v100_ecnu.slurm)

printf 'PREP_JOB=%s TRAIN_JOB=%s\n' "${PREP_JOB}" "${TRAIN_JOB}"
```

不能在预处理结束时删除 preprocessed，因为后续 V100 训练仍需要它。脚本只会在训练、103 例内部验证、checkpoint 和摘要发布全部成功后清理：

```text
nnUNet_raw/Dataset264.../{imagesTr,labelsTr,imagesTs,labelsTs}
nnUNet_preprocessed/Dataset264.../nnUNetPlans_3d_fullres
completion_case_folders
```

保留 `nnUNet_results`、`published`、`nnUNetPlans.json`、`dataset_fingerprint.json`、`gt_segmentations`、split 和审计文件。清理还要求 emergency marker 中的 dataset 和绝对路径完全匹配，防止误删。

目录权限就绪后，在 ECNU 项目根目录提交：

```bash

```

准备任务必须出现以下收口证据后，V100 训练才能通过 `afterok` 启动：

```text

split train/val/test=1035/103/104
COMPLETION_ONLINE_SPLIT_PASS
COMPLETION_PLANS_PASS
S2_COMPLETION_PREP_PASS
```

Dataset264 应包含：`imagesTr=4552`、`labelsTr=1138`、`imagesTs=416`、`labelsTs=104`。训练开始后必须确认 GPU 为 V100 32GB、real-only checkpoint 成功加载、loss 有限且无 OOM/NaN/Inf。


必须满足：

```text

work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-corrected-labels/

```

第二个目录不能漏。当前 train+val 中有 2 例使用 corrected label：`BraTS-MET-01094-003` 和 `BraTS-MET-01184-002`。任一目标文件缺失时，准备任务会在物化或 integrity check 阶段失败，不会带病进入训练。

第三个目录是官方无标签 validation，只在第 9 节使用。本地已核对为 179 个病例，每例恰好 `t1n/t1c/t2w/t2f` 四个文件，共 716 个 NIfTI，没有 `seg`；因此这批官方 validation 不需要先走 G1 缺失 T2W 填补。

1. 校验 G2 mapping/split 字段和数量合同 `823/103/104`。
2. 以 `source_case_id` 检查 train/val/test 不重叠。
3. 以 patient group 检查同一患者不跨 split。
4. 生成独立目录 `data/splits/current/`。
5. 只物化 823 train + 103 val，生成 Dataset263。
6. 仅对 `3d_fullres` 运行或复用 Dataset263 的 nnU-Net preprocess。

## 7. 训练行为与输出

训练入口再次执行缓存 ID 审计，并再次要求 `823/103`。之后：

1. 没有 checkpoint：从头训练一个固定模型。
2. 只有 `checkpoint_latest.pth`：自动使用 `--c` 续训。
3. final checkpoint 存在但 validation 不完整：只运行 `--val`。
4. final checkpoint、summary 和 103 个 validation 预测完整：直接跳过。

## 8. 内部 103 例官方兼容指标

S2 必须使用官方 `BraTS_evaluation` 评估固定 103 例 validation。不要用 G2 synthetic QC 代替：G2 QC 负责检查合成数据质量，不是 S2 分割排行榜评估器。

这一节只产生内部 proxy 指标，作用是判断 checkpoint 是否值得送去官方 validation。这里的 JSON、CSV 和 103 个预测都不能上传 Synapse。

```text
      nnunet_case_mapping_realonly_train_val.csv
```

训练已经完成时，可以单独提交评估任务，不需要重跑 G2，也不需要重跑 S2 训练：

4. 检查 current 模式的 `checkpoint_final.pth`。
5. 调用 `nnUNetv2_predict -f 0`，并要求输出 ID 集与输入完全一致。
6. 逐例检查标签为整数且只在 `{0,1,2,3,4}` 内。
7. 逐例检查预测与原图的 dimensions、spacing、origin、orientation 和 affine 完全对齐。

```bash
  --export=ALL,S2_EXPERIMENT_MODE=legacy,G2_REFRESH_REALONLY=0,S2_RUN_PREPROCESS=auto \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_prepare_nyu.slurm)

  --dependency=afterok:${LEGACY_PREP_JOB} \

  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm
```

legacy 模式：

1. 使用 `nnunet_case_mapping_master.csv` 反查历史病例身份。
2. 从现有 Dataset260 的 1035 个 ID 和 `fold_0/validation` 的 207 个结果恢复 828/207。
3. 不信任可能被失败五折任务覆盖的旧 split 文本。
4. 使用独立 `data/splits/legacy/`。
5. 保留 Dataset260 和原 checkpoint，不写入 Dataset263。
6. 只能作为历史结果，不用于当前 paired real-only vs real+synth 结论。

如果 Dataset260、预处理缓存或历史 validation 结果缺失，不得猜测划分，也不得用 current 模式产物替代。

## 12. 常见失败及处理

| 报错 | 含义 | 处理 |
|---|---|---|
| `count contract failed` | G2 数量不再是当前合同 | 停止，核对 mapping/split 版本 |
| `Patient groups cross` | 同一患者跨 split | 停止，修复 G2 split |
| `cache ID space differs` | split、raw、preprocess ID 不一致 | 不训练；清理错误的新 dataset 或更换新 Dataset ID 后重新 preprocess |
| `S2_DATASET_NAME must start` | Dataset ID 与目录名不一致 | 同时修正 ID 和 name |
| `mode is locked to dataset` | current/legacy 模式与 Dataset ID/name 被混用 | 删除手动 Dataset 覆盖，只传 `S2_EXPERIMENT_MODE` |
| `CUDA is unavailable` | GPU/环境错误 | 核对 Slurm GPU 资源和 Conda PyTorch |
| `Missing source-case mapping` | validation mapping 与预测 ID 不一致 | 重新运行对应模式 preparation |
| `Missing final checkpoint` | 尚未训练完成 | 等训练完成或检查训练日志 |
| `Official validation case-count mismatch` | 服务器不是完整的 179 例官方 validation | 重新同步并核对 `Validation/` |
| `unexpected_nifti` | 官方病例中混入 `seg` 或未知 NIfTI | 不推理；清理错误放置的数据副本 |
| `prediction filename/coverage mismatch` | 预测缺例、病例名错误或有旧预测残留 | 使用专用官方输出目录后重跑 |
| `array dimensions/spacing/origin/orientation differs` | 预测没有保持官方 native space | 不打包；检查后处理和 nnU-Net 导出流程 |
| `illegal labels` | 输出标签不在 `{0,1,2,3,4}` | 不提交；检查类别映射和 checkpoint |

不要通过手改 split、复制 `.b2nd`、重命名 prediction 或关闭审计来绕过错误。
