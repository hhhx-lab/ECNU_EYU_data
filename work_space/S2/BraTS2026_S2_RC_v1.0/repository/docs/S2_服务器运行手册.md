# S2 服务器运行手册

## 1. 当前结论

S2 是当前最优先跑通的 real-only 主基线，路线是 nnU-Net v2 + RC-aware trainer。S2 不依赖预先存在的 G2 结果文件；它会先从服务器 raw data 生成 G2 real-only mapping/split，并自动跳过缺 `t2w` 或缺任一必要文件的病例。

## 2. 服务器默认路径

示例默认项目根目录：

```bash
PROJECT_ROOT=/scratch/bf2260/ECNU_EYU_data
```

如果实际路径不同，提交 Slurm 时用 `PROJ=/真实项目根目录` 覆盖。

## 3. 环境配置

先按同目录下的环境文件创建并自检 conda 环境：

```text
work_space/S2/BraTS2026_S2_RC_v1.0/repository/docs/S2_experiment.txt
```

S2 Slurm 默认使用：

```text
CONDA_SH=/share/apps/anaconda3/2025.06/etc/profile.d/conda.sh
CONDA_ENV=brats2026_s2
```

如果服务器 conda 激活脚本或环境名不同，提交时通过 `--export=ALL,CONDA_SH=...,CONDA_ENV=...` 覆盖。正式运行前至少确认 `torch`、`nnunetv2`、`batchgenerators`、`batchgeneratorsv2`、`nibabel`、`SimpleITK` 能 import，并且 `nnUNetv2_plan_and_preprocess`、`nnUNetv2_train` 两个命令存在。

## 4. 输入数据

S2 Slurm 首先读取原始数据：

```text
work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training/
```

然后运行：

```text
work_space/G2/code/g2_build_realonly_from_raw.py
```

生成：

```text
work_space/G2/results/manifests/nnunet_case_mapping_realonly.csv
work_space/G2/results/splits/splits_final_train_val_test.json
```

不完整病例会记录在：

```text
work_space/G2/results/manifests/realonly_skipped_incomplete_cases.csv
```

每个病例必须有：

```text
<case_id>-t1n.nii.gz
<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

通道顺序固定为：

```text
0000 = t1n
0001 = t1c
0002 = t2w
0003 = t2f
```

## 6. Slurm 会做什么

脚本位置：

```text
work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm
```

执行步骤：

1. 检查 S2 repository、raw data、G2 raw intake 脚本、conda 激活脚本。
2. 激活 `brats2026_s2` 环境。
3. 从 raw data 刷新 G2 real-only mapping 和 split。
4. 缺 `t2w` 或缺任一必要文件的病例只记录到 skipped CSV，不进入训练。
5. 从 G2 split 写出 `train_full.txt`、`val_full.txt`、`test_internal_locked.txt`。
6. 从全量 mapping 生成 train+val-only mapping。
7. 用 symlink 物化 nnU-Net raw dataset。
8. 执行 `nnUNetv2_plan_and_preprocess -d 260 --verify_dataset_integrity`。
9. 执行 `bash train.sh`。

## 8. 运行后检查

```bash
squeue -u $USER
tail -f ${PROJECT_ROOT}/logs/s2_realonly_<jobid>.out
```

日志里应该看到：

```text
valid_cases=...
skipped_cases=...
train: ...
val: ...
test locked: ...
conversion finished
nnU-Net plan and preprocess
Starting BraTS2026 RC training
```

如果当前 raw data 中完整病例数仍为 1295，默认结果应是 train 829、val 207、test 259。若缺 `t2w` 病例被跳过，数量会自动按完整病例数重算。

`dataset.json` 应该写在：

```text
work_space/S2/data/nnunet_raw/Dataset260_BraTS2026_MET_RealOnly/dataset.json
```

里面应包含：

```text
labels = background, NETC, SNFH, ET, RC
```

如果完整病例数仍为 1295，则 `numTraining` 应为 train+val = 1036；如果有病例因缺 `t2w` 被跳过，`numTraining` 会随实际 train+val 数量变化。


## 10. 调参位置

主要文件：

```text
work_space/S2/BraTS2026_S2_RC_v1.0/repository/custom_nnunet/nnUNetTrainerBraTS2026RC.py
```

优先级：

1. RC CE weight：当前 `[1,1,1,1,3]`，可试 3、5、10。
2. epoch：当前 `num_epochs = 1000`。
3. `oversample_foreground_percent`：当前 `0.33`，小病灶漏检严重时可提高。
4. patch/batch：优先交给 nnU-Net plan，不要手工乱改。

## 11. 注意事项

1. internal locked test 只写清单，不进 `Dataset260_BraTS2026_MET_RealOnly`。
2. 不要改 `S2_DATASET_ID=260`，除非同时改所有说明和物化路径。
3. `train.py` 和 `inference.py` 不是当前入口；入口是 `train.sh` 和 `infer.sh`。
4. `train.sh` 会把自定义 trainer 同步到当前 Python 环境的 nnU-Net trainer 目录，避免 `-tr nnUNetTrainerBraTS2026RC` 找不到。
