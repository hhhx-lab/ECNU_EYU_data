# S2 服务器运行手册

## 1. 默认正式口径

S2 默认运行当前 G2 patient-group real-only fixed split，不运行交叉验证：

```text
experiment mode       current
train                 823
validation            103
internal locked test  104
dataset               Dataset263_BraTS2026_MET_RealOnly_Current
nnU-Net CLI key       0
```

`fold_0/` 只是 nnU-Net 要求的 API/结果目录键，不代表五折。脚本拒绝 folds 1-4 和 Slurm Array。

历史 Dataset260 模型的 `828/207/259` 划分只用于历史复核，不能作为当前 real-only vs real+synth paired baseline。历史模式见第 11 节。

## 2. 当前输入契约

准备任务默认读取：

```text
work_space/G2/results/manifests/nnunet_case_mapping_realonly.csv
work_space/G2/results/splits/splits_final_train_val_test.json
```

必须满足：

1. mapping 为 1030 个 authentic-T2W 病例。
2. split 为 `823 train / 103 val / 104 test`。
3. 同一 `BraTS-MET-xxxxx` patient group 不跨 split。
4. train/val 每例存在 `t1n/t1c/t2w/t2f/seg`。
5. 标签只允许 `{0,1,2,3,4}`。
6. 通道固定为 `0000=t1n, 0001=t1c, 0002=t2w, 0003=t2f`。

当前 train+val 共 926 例进入 nnU-Net raw/preprocessed；104 例 locked test 不参与训练、调参或 checkpoint 选择。

版本化 mapping 中的文件路径是相对项目根目录。服务器必须同时具有：

```text
work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training/
work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-corrected-labels/
```

第二个目录不能漏。当前 train+val 中有 2 例使用 corrected label：`BraTS-MET-01094-003` 和 `BraTS-MET-01184-002`。任一目标文件缺失时，准备任务会在物化或 integrity check 阶段失败，不会带病进入训练。

## 5. 当前正式运行命令

```bash
PROJECT_ROOT=/scratch/bf2260/ECNU_EYU_data
cd "${PROJECT_ROOT}"
mkdir -p logs

PREP_JOB=$(sbatch --parsable \
  --export=ALL,S2_EXPERIMENT_MODE=current,G2_REFRESH_REALONLY=0,S2_RUN_PREPROCESS=auto \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_prepare_nyu.slurm)

TRAIN_JOB=$(sbatch --parsable \
  --dependency=afterok:${PREP_JOB} \
  --export=ALL,S2_EXPERIMENT_MODE=current \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm)

EVAL_JOB=$(sbatch --parsable \
  --dependency=afterok:${TRAIN_JOB} \
  --export=ALL,S2_EXPERIMENT_MODE=current,CONDA_ENV=brats_eval \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_official_eval_nyu.slurm)

printf 'PREP_JOB=%s TRAIN_JOB=%s EVAL_JOB=%s\n' "${PREP_JOB}" "${TRAIN_JOB}" "${EVAL_JOB}"
```

禁止添加 `--array`。不要手动设置 `S2_REUSE_EXISTING_FIXED_SPLIT`；current 模式固定为 `0`。

## 6. 准备任务行为

current preparation 会：

1. 校验 G2 mapping/split 字段和数量合同 `823/103/104`。
2. 以 `source_case_id` 检查 train/val/test 不重叠。
3. 以 patient group 检查同一患者不跨 split。
4. 生成独立目录 `data/splits/current/`。
5. 只物化 823 train + 103 val，生成 Dataset263。
6. 仅对 `3d_fullres` 运行或复用 Dataset263 的 nnU-Net preprocess。
7. 比较 fixed split、raw Dataset263 和预处理缓存三套 ID，必须完全相等。

输出：

```text
work_space/S2/BraTS2026_S2_RC_v1.0/repository/data/splits/current/
  train_fixed.txt
  val_fixed.txt
  test_internal_locked.txt
  test_internal_locked_source_ids.txt
  fixed_split_membership.csv
  fixed_split_summary.json
  fixed_split_cache_audit.json
  nnunet_case_mapping_realonly_train_val.csv

work_space/S2/data/nnunet_raw/
  Dataset263_BraTS2026_MET_RealOnly_Current/

work_space/S2/data/nnunet_preprocessed/
  Dataset263_BraTS2026_MET_RealOnly_Current/
```

验收：

```bash
python -m json.tool \
  work_space/S2/BraTS2026_S2_RC_v1.0/repository/data/splits/current/fixed_split_summary.json

python -m json.tool \
  work_space/S2/BraTS2026_S2_RC_v1.0/repository/data/splits/current/fixed_split_cache_audit.json
```

必须确认：

```text
effective_counts.train=823
effective_counts.val=103
effective_counts.test_internal_locked=104
source_identity_disjoint=true
patient_group_disjoint=true
cache audit status=pass
cache audit id_sets_equal=true
cache audit dataset_count=926
cache audit preprocessed_count=926
```

任何一项不满足都不要提交训练任务。

## 7. 训练行为与输出

训练入口再次执行缓存 ID 审计，并再次要求 `823/103`。之后：

1. 没有 checkpoint：从头训练一个固定模型。
2. 只有 `checkpoint_latest.pth`：自动使用 `--c` 续训。
3. final checkpoint 存在但 validation 不完整：只运行 `--val`。
4. final checkpoint、summary 和 103 个 validation 预测完整：直接跳过。

输出：

```text
work_space/S2/data/nnunet_results/
  Dataset263_BraTS2026_MET_RealOnly_Current/
  nnUNetTrainerBraTS2026RC__nnUNetPlans__3d_fullres/
  fold_0/
    checkpoint_latest.pth
    checkpoint_best.pth
    checkpoint_final.pth
    validation/summary.json
    validation/*.nii.gz
```

## 9. 无标签推理

输入目录必须是 nnU-Net 四通道格式：

```text
<case>_0000.nii.gz
<case>_0001.nii.gz
<case>_0002.nii.gz
<case>_0003.nii.gz
```

提交：

```bash
sbatch \
  --export=ALL,S2_EXPERIMENT_MODE=current,S2_INFERENCE_INPUT=/path/to/nnunet_input \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_infer_nyu.slurm
```

默认输出：

```text
work_space/S2/results/realonly_current_fixed_inference/
```

推理入口会在调用 `nnUNetv2_predict` 前扫描整个输入目录；缺任一通道、多出 `0004` 等未知通道、混入未按 nnU-Net 命名的 NIfTI，都会立即停止。

## 11. 历史 Dataset260 复核模式

历史模式仅用于保护和复核已经完成的 `828 train / 207 val / 259 test` checkpoint：

```bash
LEGACY_PREP_JOB=$(sbatch --parsable \
  --export=ALL,S2_EXPERIMENT_MODE=legacy,G2_REFRESH_REALONLY=0,S2_RUN_PREPROCESS=auto \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_prepare_nyu.slurm)

sbatch \
  --dependency=afterok:${LEGACY_PREP_JOB} \
  --export=ALL,S2_EXPERIMENT_MODE=legacy \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm
```

legacy 模式：

1. 使用 `nnunet_case_mapping_master.csv` 反查历史病例身份。
2. 从现有 Dataset260 的 1035 个 ID 和 `fold_0/validation` 的 207 个结果恢复 828/207。
3. 不信任可能被失败五折任务覆盖的旧 split 文本。
4. 使用独立 `data/splits/legacy/`。
5. 保留 Dataset260 和原 checkpoint，不写入 Dataset263。
6. 只能作为历史结果，不用于当前 paired real-only vs real+synth 结论。

如果 Dataset260、预处理缓存或历史 validation 结果缺失，不得猜测划分，也不得用 current 模式产物替代。

## 12. 常见失败及处理

| 报错 | 含义 | 处理 |
|---|---|---|
| `count contract failed` | G2 数量不再是当前合同 | 停止，核对 mapping/split 版本 |
| `Patient groups cross` | 同一患者跨 split | 停止，修复 G2 split |
| `cache ID space differs` | split、raw、preprocess ID 不一致 | 不训练；清理错误的新 dataset 或更换新 Dataset ID 后重新 preprocess |
| `S2_DATASET_NAME must start` | Dataset ID 与目录名不一致 | 同时修正 ID 和 name |
| `mode is locked to dataset` | current/legacy 模式与 Dataset ID/name 被混用 | 删除手动 Dataset 覆盖，只传 `S2_EXPERIMENT_MODE` |
| `CUDA is unavailable` | GPU/环境错误 | 核对 Slurm GPU 资源和 Conda PyTorch |
| `Missing source-case mapping` | validation mapping 与预测 ID 不一致 | 重新运行对应模式 preparation |
| `Missing final checkpoint` | 尚未训练完成 | 等训练完成或检查训练日志 |

不要通过手改 split、复制 `.b2nd`、重命名 prediction 或关闭审计来绕过错误。
