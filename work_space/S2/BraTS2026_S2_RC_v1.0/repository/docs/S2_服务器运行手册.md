# S2 服务器运行手册

## 1. 当前状态和本手册目标

S2 使用 nnU-Net v2 `3d_fullres` 和 `nnUNetTrainerBraTS2026RC` 训练四模态 BraTS-MET 分割模型。

当前服务器已经完成 real-only fold0：

- 828 例 train。
- 207 例 val。
- 259 例 internal locked test 未参与训练和调参。
- fold0 已完成 1000 epochs 和 207 例验证推理。

旧脚本只运行 fold0。本手册对应的新流程会保留现有 fold0，并继续完成 folds 1-4，最后把五折 out-of-fold 预测交给官方 `BraTS_evaluation` 计算 lesionwise DSC、NSD 和 small-instance 指标。

## 2. 完整流程

```text
raw BraTS-MET data
    |
    v
G2 real-only mapping + fixed train/val/test
    |
    v
S2 five-fold split builder
    |-- fold0: 保持现有 828/207 不变
    |-- fold1-4: 将 fold0 的 828 个训练病例稳定拆成四组验证集
    |
    v
Dataset260 materialization + nnU-Net preprocessing（只运行一次）
    |
    v
Slurm Array: folds 0-4，每个 task 使用 1 张 GPU
    |
    v
五折 out-of-fold predictions
    |
    v
BraTS_evaluation MET metrics
```

禁止让五个训练 task 分别执行数据清理或预处理。准备和训练已经拆成两个 Slurm 阶段。

| 脚本 | GPU | 作用 |
|---|---:|---|
| `04_s2_realonly_prepare_nyu.slurm` | 0 | 生成 G2 mapping、五折划分、Dataset260 和预处理数据 |
| `04_s2_realonly_nyu.slurm` | 每个 array task 1 张 | 训练指定 fold，自动跳过完成项、自动续训中断项 |
| `04_s2_realonly_official_eval_nyu.slurm` | 0 | 合并五折 out-of-fold 预测并计算官方兼容指标 |
| `04_s2_realonly_infer_nyu.slurm` | 1 | 使用 folds 0-4 ensemble 对无标签输入做最终推理 |

## 5. 输入数据和病例口径

默认 raw data：

```text
work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training/
```

每个病例必须有：

```text
<case_id>-t1n.nii.gz
<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

nnU-Net 通道顺序固定为：

```text
0000 = t1n
0001 = t1c
0002 = t2w
0003 = t2f
```

标签只允许 `{0,1,2,3,4}`。G2 intake 优先使用 clean corrected label；没有 clean corrected label 且 raw seg 含非法值的病例会被跳过。

为保证 folds 1-4 与已经完成的 fold0 使用同一病例池，准备脚本默认继续排除 fold0 当时排除的两个病例：

```text
BraTS-MET-01094-002
BraTS-MET-01184-002
```

默认变量：

```text
S2_PRESERVE_FOLD0_EXCLUSIONS=1
```

不要在继续 folds 1-4 时把它改成 `0`。如果以后拿到这两个病例的 clean corrected label 并决定纳入，必须建立新实验并重新训练 fold0，不能把不同病例池的 folds 混合汇总。

## 6. 五折规则

五折脚本保持现有 fold0 不变：

```text
fold0 val = 原固定 val 207 例
```

原 fold0 的 828 个 train 病例通过固定 SHA256 seed 排序后，平衡拆成四组，分别作为 folds 1-4 的验证集。最终每个 CV-pool 病例只作为验证病例出现一次；locked test 永远不进入任何训练或验证 fold。

默认 1035 例 CV pool 下，每折应为：

```text
train = 828
val   = 207
```

生成文件：

```text
data/splits/train_fold0.txt ... train_fold4.txt
data/splits/val_fold0.txt   ... val_fold4.txt
data/splits/test_internal_locked.txt
data/splits/five_fold_membership.csv
data/splits/five_fold_summary.json
data/splits/nnunet_case_mapping_realonly_train_val.csv
```

`five_fold_summary.json` 记录输入 mapping/split 的 SHA256、每折数量和每个 split 文件的 SHA256，服务器交接时应保留。

## 7. 当前服务器继续 folds 1-4

这是当前推荐命令。先进入项目根目录并创建日志目录：

这是续接已经完成的 fold0，不是重开实验。准备任务默认使用
`G2_REFRESH_REALONLY=0` 和 `S2_RUN_PREPROCESS=auto`，复用 fold0 当时的
mapping、split、Dataset260 预处理结果和病例 ID，只新增五折划分文件。
补跑期间禁止设置 `G2_REFRESH_REALONLY=1`；重新扫描和排除病例可能改变
nnU-Net ID，造成 fold0 预测、GT 和 folds 1-4 数据口径不一致。

```bash
PROJECT_ROOT=/scratch/bf2260/ECNU_EYU_data
cd ${PROJECT_ROOT}
mkdir -p logs
```

提交一次 CPU 准备任务：

```bash
PREP_JOB=$(sbatch --parsable \
  --export=ALL,G2_REFRESH_REALONLY=0,S2_RUN_PREPROCESS=auto \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_prepare_nyu.slurm)
echo "S2 preparation job: ${PREP_JOB}"
```

准备成功后，提交 folds 1-4。四个 fold 可以并行，各使用一张 GPU：

```bash
CV_JOB=$(sbatch --parsable \
  --dependency=afterok:${PREP_JOB} \
  --array=1-4%4 \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm)
echo "S2 folds 1-4 array job: ${CV_JOB}"
```

`--array=1-4%4` 表示提交 folds 1、2、3、4，最多同时运行 4 个。调度器可以让它们在不同节点开始，不需要等待同一节点同时空出 4 张 GPU。

项目根路径、conda 激活脚本或环境名不同，使用：

```bash
PREP_JOB=$(sbatch --parsable \
  --export=ALL,PROJ=/真实项目根目录,CONDA_SH=/path/to/conda.sh,CONDA_ENV=brats2026_s2 \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_prepare_nyu.slurm)

CV_JOB=$(sbatch --parsable \
  --dependency=afterok:${PREP_JOB} \
  --array=1-4%4 \
  --export=ALL,PROJ=/真实项目根目录,CONDA_SH=/path/to/conda.sh,CONDA_ENV=brats2026_s2 \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm)
```

## 9. 自动跳过和自动续训

`train.sh` 的默认行为：

1. 对应 fold 同时存在 `checkpoint_final.pth`、`validation/summary.json` 和足量验证预测：认为训练与验证完整，直接成功退出。
2. 存在 `checkpoint_final.pth`，但验证 summary 或预测不完整：自动使用 `--val`，只补验证，不重新训练。
3. 不存在 final、但存在 `checkpoint_latest.pth`：自动添加 `--c`，从最近 checkpoint 续训。
4. final 和 latest 都不存在：从 epoch 0 开始训练。

默认变量：

```text
S2_SKIP_COMPLETED=1
S2_CONTINUE=auto
```

因此完整数组包含 fold0 也不会覆盖已经完成的 fold0；如果 fold0 服务器只保留了 checkpoint、没有保留验证预测，脚本会自动补跑验证。不要手工删除 checkpoint；需要重跑某个 fold 时，应先把旧 fold 目录完整归档为另一个实验，而不是在原目录覆盖。

单独重提失败的 fold，例如 fold3：

```bash
sbatch --array=3 \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_nyu.slurm
```

如果 fold3 有 `checkpoint_latest.pth`，会自动续训；没有则从头训练。

## 12. 五折完成检查

```bash
RESULT_BASE=/scratch/bf2260/ECNU_EYU_data/work_space/S2/data/nnunet_results/Dataset260_BraTS2026_MET_RealOnly/nnUNetTrainerBraTS2026RC__nnUNetPlans__3d_fullres

for FOLD in 0 1 2 3 4; do
  echo "===== fold ${FOLD} ====="
  test -f "${RESULT_BASE}/fold_${FOLD}/checkpoint_final.pth" || echo "MISSING checkpoint_final"
  test -f "${RESULT_BASE}/fold_${FOLD}/validation/summary.json" || echo "MISSING validation summary"
  find "${RESULT_BASE}/fold_${FOLD}/validation" -maxdepth 1 -type f -name '*.nii.gz' | wc -l
done
```

每折预测数应等于对应 `val_foldN.txt` 行数。只有五个 fold 都有 final checkpoint、summary 和完整预测，real-only 五折训练才算完成。

## 13. 官方兼容指标

五折训练完成后提交：

```bash
METRICS_JOB=$(sbatch --parsable \
  --dependency=afterok:${CV_JOB} \
  --export=ALL,CONDA_ENV=brats_eval \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_official_eval_nyu.slurm)
echo "S2 official metrics job: ${METRICS_JOB}"
```

该任务会把每个病例唯一一次 out-of-fold 预测合并后运行：

```text
brats-evaluate --config mets
brats-parse-metrics mets
```

脚本会通过 `nnunet_case_mapping_realonly_train_val.csv` 将
`BraTSMET_000001` 形式的 nnU-Net ID 恢复为官方
`BraTS-MET-xxxxx-xxx` 病例名。随后强制检查 JSON 中的评估病例数与五折
总数一致且 `missings` 为空；官方评估器如果跳过任何病例，任务会直接失败。

默认内部阈值：

```text
VOL_THRESHOLD=27
OVERLAP_THRESHOLD=0.2
```

需要覆盖时：

```bash
sbatch \
  --export=ALL,CONDA_ENV=brats_eval,VOL_THRESHOLD=27,OVERLAP_THRESHOLD=0.2 \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_official_eval_nyu.slurm
```

输出：

```text
work_space/S2/results/realonly_5fold_cv/panoptica_evaluation_summary.json
work_space/S2/results/realonly_5fold_cv/leaderboard_metrics.csv
```

`validation/summary.json` 中的普通体素级 Dice 只是内部辅助指标；正式比较必须读取 `leaderboard_metrics.csv` 中 ET/RC/TC/WT 的 lesionwise DSC、NSD 和 small-instance TP/FN/FP/F1。最终排行榜分数仍以 Synapse 2026 Task1 服务器为准。

<case_id>_0001.nii.gz = T1C

<case_id>_0003.nii.gz = T2F

提交：

```bash
INFER_JOB=$(sbatch --parsable \
  --export=ALL,S2_INFERENCE_INPUT=/path/to/nnunet_input \
  work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/04_s2_realonly_infer_nyu.slurm)
echo "S2 inference job: ${INFER_JOB}"
```

默认输出：

```text
work_space/S2/results/realonly_5fold_inference/
```

`infer.sh` 默认传入：

```text
-tr nnUNetTrainerBraTS2026RC
-f 0 1 2 3 4
```

并在推理前检查五个 `checkpoint_final.pth`。临时冒烟测试可以用 `S2_FOLDS=0`，但 fold0-only 结果不能作为最终五折 ensemble 结果。

## 15. real-only 完成后下一步

本手册完成的是 S2 real-only 五折基线。S2 最终任务还包括 real+synthetic augmentation 消融，但必须等 G1 生成数据通过 G2 accepted/rejected QC 后再建立独立数据集和结果目录。

禁止把 synthetic 数据直接混入 Dataset260，也禁止覆盖 real-only checkpoint。后续增强实验应使用新的 dataset ID、独立 output 路径，并复用完全相同的五折验证病例，才能公平比较。

## 16. 常见问题

### 准备任务成功，但训练提示缺少 fold split

检查：

```bash
ls work_space/S2/BraTS2026_S2_RC_v1.0/repository/data/splits/train_fold*.txt
ls work_space/S2/BraTS2026_S2_RC_v1.0/repository/data/splits/val_fold*.txt
```

缺失时重新运行准备任务，不要手工拼接 split。

### 新 fold 报无法续训

新 `train.sh` 不再无条件使用 `--c`。确认服务器拉到了最新代码，并在日志里看到：

```text
No resumable checkpoint found; starting fold N from scratch.
```

### 多个 array task 同时修改 Dataset260

说明提交方式错误。训练 array 只负责训练；数据 materialization 和 preprocessing 只能由 `04_s2_realonly_prepare_nyu.slurm` 执行一次。

### fold0 被重新训练

默认 `S2_SKIP_COMPLETED=1` 只会在 final checkpoint、validation summary 和 207 个预测全部存在时跳过。检查 fold0 final checkpoint 是否仍在标准结果目录，以及 `nnUNet_results` 是否指向原服务器结果路径。

### 官方指标任务提示找不到命令

说明提交时激活的不是独立 `brats_eval` 环境，或该环境尚未提供 `BraTS-evaluation`。不要在运行中的 S2 训练环境里临时混装依赖。
