## 2. G1 结果到来前必须完成

### 2.1 数据身份复核

1. 检查 `nnunet_case_mapping_master.csv` 行数和唯一性。
2. 检查 `nnunet_case_mapping_realonly.csv` 是 master 的 authentic-T2W 子集。
3. 检查 fake/broken 清单与 master 的 `completion_required=True` 完全一致。
4. 检查 corrected seg 路径存在且 label 值域为 `{0,1,2,3,4}`。
5. 检查 master/real-only membership 患者组交叉为 0。

### 2.2 V2 交付约定

1. 明确正式 run ID 和 seed。
2. 锁定四模态 checkpoint。
3. 锁定 sampling method、sampling steps、noise schedule 和 crop size。
4. 只从 `g1_v2_source_manifest.csv` 的 allowed 行取 source。
5. 先生成 10-20 例 smoke，再扩大批次。
6. 要求 V2 输出旁保存 `generation_config.json`。

### 2.3 V3 交付约定

1. 锁定 VAE、EncDec、BBDM checkpoint。
2. 锁定 `bbdm_s`、seed、synthesis type 和 validation run。
3. 目标病例必须来自 265 例 completion 清单。
4. 输出必须包含完整四模态和 seg，便于病例内几何检查。
5. run root 必须包含 config、inference record、manifest 和 log。

## 5. 可立即准备的人工复核

1. 从 V2 smoke 批次抽取每中心、每病灶大小、含/不含 RC 的病例。
2. 每例查看三平面四模态、seg overlay、generation support 和边界。
3. V3 对比 source 的 t1n/t1c/t2f/seg 是否逐体素保持一致。
4. V3 对比生成 T2W 的脑区覆盖、肿瘤信号、z 连续性和边缘伪影。
5. 将审批写入 run root 的 `g2_approval_manifest.csv`，不手改 accepted 输出。

## 6. 可立即准备的 teacher 检查

teacher 不是当前自动放行的一部分。正式批次到来前需要确定：

1. 使用哪一个冻结的 real-only segmentation checkpoint。
2. checkpoint 对应的 fixed split 和通道顺序。
3. teacher 仅做辅助复核，不能用训练过同一 synthetic 的模型自证质量。
4. 输出至少包括四类 Dice、病灶数差、漏检大病灶数和额外大病灶数。
5. teacher 未运行时字段保持空值/`not_run`，病例保持 pending，不能填伪指标。

## 7. 可立即准备的消融设计

必须建立成对实验：

```text
A: real-only
B: real + V3 completion
C: real + accepted V2 augmentation
D: real + V3 completion + accepted V2 augmentation
```

四组实验必须共享：

1. 同一 patient-group fixed split。
2. 同一模型代码和初始化策略。
3. 同一训练轮数、增强和调参预算。
4. 同一真实 val/test。
5. 相同官方 evaluation 工具版本。

V3 completion 修复的是数据完整性；V2 augmentation 测试的是新增合成数据价值，两者必须分开报告。

## 8. 正式批次到达后的顺序

1. V2 先 composer，V3 先 completion adapter。
2. 运行技术硬门 QC。
3. 查看 rejected 原因并回传 G1。
4. 对 pending 病例做人工/teacher 复核。
5. 重新运行 intake 生成 accepted manifest。
6. 先用 materializer 的 `manifest-only` 做源文件预检。
7. 再以 symlink/hardlink/copy 物化双视图。
8. 运行 nnU-Net integrity。
9. 启动成对消融。
10. 用官方 lesionwise DSC/NSD 和 small-instance F1 收口。
