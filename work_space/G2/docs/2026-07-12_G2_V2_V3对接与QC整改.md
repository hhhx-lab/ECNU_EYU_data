# 2026-07-12 G2 V2/V3 对接与 QC 整改

## 1. 变更状态

- 日期：2026-07-12
- 状态：已完成（代码、接口、文档与轻量 fixture 验收）
- 责任模块：`work_space/G2`
- 影响接口：G1 Diffusion V2、G1 缺失模态 V3、S1-S5 数据入口
- 原则：先保证无泄漏、可追溯、可复现和可训练，再讨论生成质量是否足够优秀。

## 2. 整改原因

G2 的任务定位仍然正确：接收 G1 生成结果，完成标准化、质量控制、训练数据转换和数据报告，并向 S1-S5 提供可复用的数据入口。但现有实现基于旧版 G1 raw output 假设，不能直接承接当前两条最新版产线。

当前必须修复的问题：

1. synthetic intake 存在未定义变量，正式接收时会崩溃。
2. train/val/test 按病例而不是患者分组，存在患者级泄漏。
3. 缺少 checkpoint、seed、配置等关键元数据时仍可能自动放行。
4. V2 和 V3 的数据语义不同，却共用同一套 synthetic ID 和物化规则。
5. V2 输出是归一化肿瘤区域生成结果，不是可直接训练的完整病例。
6. V3 completion 应替换原病例 T2W，而不是新增 synthetic 病例。
7. 部分 QC 字段仍是常量、占位值或名称与实际计算不一致。
8. 当前物化脚本没有完整处理 fixed split、多 run、旧目录残留和 S1-S5 两类数据入口。

## 3. 两条 G1 产线的目标契约

### 3.1 G1 Diffusion V2

V2 属于 segmentation-conditioned synthetic augmentation。

原始输入：

```text
真实 source 病例四模态 + seg
```

G1 原始输出：

```text
由 seg 条件生成的四模态局部区域结果
```

G2 必须执行：

1. 按文件名解析并分组病例，禁止把同一平铺目录误判为一个病例。
2. source 只能来自 master split 的 train，且必须使用真实 T2W。
3. 从 source manifest 读取真实四模态与 corrected seg。
4. 将 V2 的归一化生成区域稳健映射到对应 source 模态强度空间。
5. 使用平滑边界把生成区域回填到 source MRI，非生成区域保持 source 数据。
6. 恢复 source affine、spacing、orientation 和 header。
7. 复制 corrected seg，输出每病例一个目录。
8. 生成可追溯的 config、log、manifest 和稳定 synthetic ID。
9. 最终作为新增 synthetic 病例，只能追加到训练集。

### 3.2 G1 缺失模态 V3

V3 属于 missing-T2W completion，不属于新增 synthetic augmentation。

G1 输出目录：

```text
run_<id>/
  inference_run.json
  <source_case_id>/
    <source_case_id>-t1n.nii.gz
    <source_case_id>-t1c.nii.gz
    <source_case_id>-t2w.nii.gz
    <source_case_id>-t2f.nii.gz
    <source_case_id>-seg.nii.gz
```

G2 必须执行：

1. 读取 `inference_run.json` 或兼容的 `generation_config.json`。
2. 保存 VAE、EncDec、BBDM checkpoint、`bbdm_s`、seed 和 validation run。
3. 保留原 `source_case_id` 和原 nnU-Net ID。
4. 只允许生成的 T2W 替换 fake/broken T2W，其他模态与 seg 使用真实 source。
5. train completion 可用于训练；val/test completion 只能用于各自固定验证或测试。
6. 不得把 val/test completion 追加到训练集，也不得因为它们不能训练而从固定 split 中删除。

## 4. Master split 规则

全队只保留一份 patient-group-aware master split。

患者分组规则：

```text
BraTS-MET-xxxxx-000
BraTS-MET-xxxxx-001
BraTS-MET-xxxxx-002
```

以上病例的 patient group 均为：

```text
BraTS-MET-xxxxx
```

强制要求：

1. 同一 patient group 只能出现在 train、val、test 中的一个集合。
2. 真实 T2W 病例的 split 必须复现 G1 V3 当前 seed=42 的 patient-group 划分，避免已运行实验失效。
3. 仅含 fake/broken T2W 的 patient group 在不改变已有真实病例 split 的前提下补充分配。
4. master membership 必须记录 `patient_group`、`t2w_status`、`eligible_for_realonly` 和 split。
5. V2 source 只允许 `split=train AND eligible_for_realonly=True`。
6. synthetic augmentation 永远只加入 train；val/test 始终只包含真实身份病例或对应 completion 修复病例。

## 5. QC 三阶段策略

### 5.1 阶段 A：技术硬门

以下任一失败立即 rejected：

1. 必需文件缺失或 NIfTI 不可读。
2. shape、spacing、affine 或 orientation 病例内不一致。
3. 图像含 NaN/Inf、常数图或异常空数据。
4. seg 非整数、值域不属于 `{0,1,2,3,4}` 或应有病灶却为空。
5. source 不可追溯、source split 不合法或存在患者级泄漏。
6. generation run、checkpoint、seed、生成模式或 source manifest 缺失。
7. V2 composition 后非 ROI 变化、边界突变或 header 恢复不符合契约。
8. V3 completion 不是 fake/broken T2W source，或错误复用了 synthetic ID。

### 5.2 阶段 B：质量复核

技术通过后计算真实指标，不允许用常量代替：

1. ROI 边界 MAE 与梯度跳变。
2. z 方向面积连续性和强度连续性。
3. source/synthetic ROI SSIM。
4. 强度漂移 p1、p50、p99。
5. ET-T1C、SNFH-T2F、SNFH-T2W 对齐指标。
6. 病灶数量、体积、tiny/small/large 分布。
7. 重复样本指纹和批次级基础特征分布。
8. teacher 或人工复核结果。

没有 teacher/人工批准时，技术通过病例进入 `pending_review`，不得伪装成 `accepted_for_training`。

### 5.3 阶段 C：训练价值验收

正式放行 synthetic augmentation 必须完成固定真实验证集消融：

```text
real-only
vs
real + accepted synthetic
```

主要指标：

1. ET/RC/TC/WT lesionwise DSC。
2. ET/RC/TC/WT lesionwise NSD。
3. ET/RC/TC/WT small-instance TP/FN/FP/F1。
4. 各中心、病灶大小和 RC 子组结果。

官方指标用于证明数据增强是否有训练价值，不替代图像质量 QC。

## 6. 输出状态

每个病例只能处于以下状态之一：

| 状态 | 含义 | 可进入训练 |
|---|---|---|
| `rejected` | 技术硬门失败 | 否 |
| `pending_review` | 技术通过，等待 teacher/人工或批次批准 | 否 |
| `accepted_for_training` | train synthetic/completion 已正式批准 | 是 |
| `accepted_for_evaluation` | val/test completion 已批准用于固定评估 | 否 |

必须分别输出 candidate、rejected、pending、accepted-training 和 accepted-evaluation manifest。

## 7. 下游物化契约

统一通道顺序：

```text
0000=t1n
0001=t1c
0002=t2w
0003=t2f
```

输出两种视图：

1. nnU-Net raw view：供 S2 使用。
2. 按 split 分区的病例目录 view：供 S1、S3、S4、S5 使用；S5 再运行自己的固定 split 预处理。

物化时必须：

1. 支持多个 synthetic manifest。
2. 使用跨 run 稳定且不冲突的 synthetic ID。
3. 输出前拒绝非空旧目录，除非操作者显式选择 clean。
4. completion 只替换对应病例 T2W。
5. synthetic augmentation 只追加到 train。
6. 同步写出 fixed split 和 materialization manifest。
7. 执行内置完整性检查；服务器具备 nnU-Net 环境时再执行官方 integrity check。
