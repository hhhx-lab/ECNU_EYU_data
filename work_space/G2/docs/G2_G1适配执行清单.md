# G2 对接 G1 V2/V3 执行清单

更新日期：2026-07-12

本文是 G2 接收 G1 输出时的逐步操作清单。正式接口以本文件、`G1_G2_diffusion_output_contract.md` 和 `2026-07-12_G2_V2_V3对接与QC整改.md` 为准。

## 1. 先区分两条产线

| 产线 | 数据含义 | G2 入口 | ID 规则 | 下游用途 |
|---|---|---|---|---|
| G1 Diffusion V2 | 基于真实 train 病例及其 seg 生成新的四模态肿瘤表现 | `g2_v2_compose_augmentation.py`，之后再运行通用 intake | 生成稳定且跨 run 唯一的 `SYN-MET-*` / `SYNMET_*` | 只可追加到 train |
| G1 缺失模态 V3 | 给原病例修复 fake/broken T2W | `g2_v3_completion_intake.py` | 保留原 `BraTS-MET-*` 和原 nnU-Net ID | 替换原病例 T2W；保持原 train/val/test 身份 |

禁止把 V3 completion 当新增 synthetic 病例，也禁止把 V2 augmentation 覆盖到原病例 ID。

## 2. 当前唯一数据口径

正式文件：

```text
work_space/G2/results/manifests/nnunet_case_mapping_master.csv
work_space/G2/results/manifests/nnunet_case_mapping_realonly.csv
work_space/G2/results/manifests/g1_v2_source_manifest.csv
work_space/G2/results/splits/splits_master_train_val_test.json
work_space/G2/results/splits/splits_final_train_val_test.json
```

当前轻量索引统计：

| 项目 | train | val | test | 合计 |
|---|---:|---:|---:|---:|
| master，包含待 completion 病例 | 1035 | 130 | 130 | 1295 |
| authentic-T2W real-only | 823 | 103 | 104 | 1030 |
| fake/broken T2W completion 目标 | 212 | 27 | 26 | 265 |

患者组规则：`BraTS-MET-xxxxx-000/001/002` 必须留在同一个 split。当前两个 membership 表的患者组交叉均为 0。

## 3. 刷新 master 与 real-only 索引

只在服务器已经放好 raw data 和 corrected labels 后执行：

```bash
python work_space/G2/code/g2_build_realonly_from_raw.py \
  --data-root /path/to/MICCAI-LH-BraTS2025-MET-Challenge-Training \
  --corrected-labels-root /path/to/MICCAI-LH-BraTS2025-MET-Challenge-corrected-labels \
  --fail-if-no-valid-cases
```

执行后必须核对：

1. master、real-only 和 skipped 数量。
2. `t2w_status` 只能是 `authentic` 或 `fake_or_broken`。
3. corrected seg 优先于非法 raw seg。
4. master 和 real-only membership 的 patient group 不跨 split。
5. `g1_v2_source_manifest.csv` 中只有 `split=train AND t2w_status=authentic` 的行可为 `allowed_as_v2_source=True`。

不要单独重新编号某一子集；master mapping 是全队病例身份表。

## 4. V2 生成前检查

1. G1 V2 训练数据只能来自 authentic-T2W 病例。
2. V2 正式 augmentation source 只能读取 `g1_v2_source_manifest.csv` 中 `allowed_as_v2_source=True` 的 823 例。
3. val/test 病例不得作为 augmentation source。
4. G1 必须记录：run ID、seed、四模态 checkpoint 或 checkpoint 目录、采样方法、采样步数、`eta`、crop size 和 source manifest。
5. `04_generate_visual_v2_nyu.slurm` 只生成单例可视化结果，不是正式批量生产入口。

V2 `generate_from_label.py` 虽在内部按 `64³` crop 推理，但最终输出与 source shape 相同，ROI 外为 0，并使用单位 affine。该输出不能直接送 S1-S5。

## 5. V2 composer

G1 正式输出目录至少包含四模态平铺文件及 `generation_config.json`：

```text
<v2_raw_root>/
  generation_config.json
  BraTS-MET-00001-000-t1n.nii.gz
  BraTS-MET-00001-000-t1c.nii.gz
  BraTS-MET-00001-000-t2w.nii.gz
  BraTS-MET-00001-000-t2f.nii.gz
```

执行：

```bash
python work_space/G2/code/g2_v2_compose_augmentation.py \
  --v2-output-root /path/to/v2_raw_root \
  --source-manifest work_space/G2/results/manifests/g1_v2_source_manifest.csv \
  --output-run-root /path/to/g2_composed/v2_run_id
```

`generation_config.json` 中的 `sampling_method`、`sampling_steps`、`eta` 和 `crop_size` 都是硬门字段。输出目录必须为空；确认整轮重做时才可加 `--overwrite`，该选项会先清空整个 composed run 目录。

composer 会：

1. 按病例聚合四模态。
2. 验证 source 属于 authentic master train。
3. 将 V2 归一化输出映射回 source 强度范围。
4. 平滑回填生成 support，ROI 外保持 source 不变。
5. 恢复 source affine/header，复制有效 seg。
6. 写出 `generation_config.json`、`generation_log.jsonl` 和 `synthetic_generation_manifest.csv`。

只要任一病例失败，脚本返回非 0。不得忽略 failed 行继续批量放行。

## 6. V2 通用 intake 与 QC

```bash
python work_space/G2/code/g2_synthetic_raw_intake_qc.py \
  --synthetic-run-root /path/to/g2_composed/v2_run_id \
  --generation-mode full_generation
```

自动输出：

```text
results/manifests/synthetic_candidate_manifest_<run_id>.csv
results/manifests/synthetic_pending_review_manifest_<run_id>.csv
results/manifests/synthetic_accepted_manifest_<run_id>.csv
results/manifests/synthetic_rejected_manifest_<run_id>.csv
results/qc/qc_metrics_<run_id>.csv
results/qc/diffusion_quality_metrics_<run_id>.csv
results/qc/qc_batch_summary_<run_id>.json
```

技术检查通过但没有审批记录时，状态必须是 `pending_review`，不能进入训练。

## 7. V3 交付前检查

V3 每个病例必须包含：

```text
<run_root>/<source_case_id>/
  <source_case_id>-t1n.nii.gz
  <source_case_id>-t1c.nii.gz
  <source_case_id>-t2w.nii.gz
  <source_case_id>-t2f.nii.gz
  <source_case_id>-seg.nii.gz
```

run root 必须包含：

```text
inference_run.json
generation_config.json
generation_log.jsonl
synthetic_generation_manifest.csv
```

元数据必须包含：

1. `generation_run_id`
2. `generator_name`
3. `seed`
4. `source_csv`
5. `vae_weights`
6. `encdec_checkpoint`
7. `bbdm_checkpoint`
8. `bbdm_s`
9. 固定 validation run

## 8. V3 completion intake

```bash
python work_space/G2/code/g2_v3_completion_intake.py \
  --completion-run-root /path/to/g1_v3_output/run_id
```

强制规则：

1. source 必须在 master mapping 中。
2. source 必须在官方 fake/broken T2W 清单中。
3. 只替换 T2W；t1n、t1c、t2f 和 seg 继续使用真实 source。
4. train completion 只能审批为 `accepted_for_training`。
5. val/test completion 只能审批为 `accepted_for_evaluation`。
6. completion 保留原 source ID 和原 nnU-Net ID。

## 9. 审批文件

技术 QC 不等于正式放行。人工或 teacher 复核后，在对应 G1/G2 run root 写入：

```csv
synthetic_raw_id,approved_for_training,approved_for_evaluation,reviewer,reason
```

规则：

1. V2 train augmentation：`approved_for_training=True`。
2. V3 train completion：`approved_for_training=True`。
3. V3 val/test completion：`approved_for_evaluation=True`。
4. 不得同时把 val/test completion 批准进 training。
5. 修改审批后重新运行 intake，不能手改 accepted manifest。

## 10. 物化给 S1-S5

统一通道：

```text
0000=t1n
0001=t1c
0002=t2w
0003=t2f
```

先用 `manifest-only` 做源文件预检：

```bash
python work_space/G2/code/g2_materialize_nnunet_dataset.py \
  --output-root /path/to/nnUNet_raw \
  --dataset-id 261 \
  --dataset-name BraTS2026_MET_Completed \
  --dataset-profile completion \
  --synthetic-accepted-manifest work_space/G2/results/manifests/synthetic_accepted_manifest_<v3_run>.csv \
  --synthetic-accepted-manifest work_space/G2/results/manifests/synthetic_accepted_evaluation_manifest_<v3_run>.csv \
  --mode manifest-only
```

real+synth 时可重复传入 manifest：

```bash
python work_space/G2/code/g2_materialize_nnunet_dataset.py \
  --output-root /path/to/nnUNet_raw \
  --case-folder-root /path/to/case_folders \
  --dataset-id 262 \
  --dataset-name BraTS2026_MET_RealSynth \
  --dataset-profile real-synth \
  --synthetic-accepted-manifest /path/to/v3_accepted_training.csv \
  --synthetic-accepted-manifest /path/to/v3_accepted_evaluation.csv \
  --synthetic-accepted-manifest /path/to/v2_accepted.csv \
  --mode symlink \
  --run-nnunet-integrity
```

脚本同时生成：

1. nnU-Net raw view，供 S2。
2. case-folder view，供 S1/S3/S4/S5；S5 再运行自己的 fixed-split preprocessing。
3. `g2_fixed_split.json` 和 `splits_final.json`。
4. `g2_materialization_manifest.csv`。
5. `g2_integrity_report.json`。

输出目录非空时默认拒绝。只有确认要删除旧物化结果时才显式使用 `--clean-output`。

`manifest-only` 也会写入轻量 dataset/manifest 文件。若正式 symlink/copy 继续使用同一个 output root 和 dataset ID，检查完预检报告后必须在正式命令中加 `--clean-output`；不确定时使用单独的 preflight output root。

V3 training 与 evaluation manifest 缺一不可：前者补 master train 的 T2W，后者补 master val/test 的 T2W。V2-only paired augmentation 若暂不纳入 completion，应显式传 `--real-mapping results/manifests/nnunet_case_mapping_realonly.csv`，不能让脚本默认读取 master 后再漏传 V3。

## 11. 最终验收

1. candidate、pending、accepted、rejected 数量可相互核对。
2. 缺 checkpoint、seed、config、manifest 或 log 的病例全部 rejected；manifest/log 还必须逐病例存在唯一成功记录。
3. V2 非 ROI 变化率满足硬门，affine/header 与 source 一致。
4. V3 只替换 fake/broken T2W，且 split 身份不变。
5. synthetic augmentation 只出现在 fixed train。
6. val/test 中没有 `SYNMET_*`。
7. nnU-Net 内置完整性检查通过；服务器有 nnU-Net 时官方 integrity check 也通过。
8. real-only 与 real+synth 必须在同一固定真实 val/test 上比较官方 lesionwise 指标。

## 12. 禁止事项

1. 不直接 intake V2 平铺输出。
2. 不把 V3 completion 重命名成 synthetic 新病例。
3. 不使用旧 `g1_met_source_cases_v1.csv` 或旧 two-way split。
4. 不使用历史 `s2_current` 通道顺序。
5. 不凭 smoke fixture 声称真实生成质量已经通过。
6. 不手改 accepted manifest 绕过审批。
7. 不复用非空 composer/materializer 输出目录混装新旧 run。
