# G2 数据生成接入与质量控制实施方案

更新日期：2026-07-12

## 1. G2 的任务边界

G2 不训练 G1 生成模型，也不替代 S1-S5 分割模型。G2 负责把 G1 输出变成可追溯、可审核、可训练、可复现实验的数据资产。

G2 的正式职责：

1. 建立全队唯一患者级 master split。
2. 维护真实病例、fake/broken T2W 和 corrected label 的身份口径。
3. 分别接收 G1 V2 augmentation 与 G1 V3 completion。
4. 完成格式、几何、数值、标签、来源和生成质量 QC。
5. 管理 pending/accepted/rejected release 状态。
6. 为 S1-S5 输出统一通道的 nnU-Net view 与 case-folder view。
7. 组织 real-only、completion 和 augmentation 成对消融。
8. 用官方 Task1 指标判断合成数据是否真正有训练价值。

## 2. 两类数据不能混为一谈

### 2.1 G1 Diffusion V2

V2 是 segmentation-conditioned augmentation。模型内部按病灶 crop 生成四模态，`generate_from_label.py` 最终保存与 source shape 相同的四模态数组，生成区外为 0，affine 为单位阵，不输出 seg。

因此 V2 raw output 不是可训练完整病例。G2 必须找回真实 source、识别生成 support、映射强度、平滑回填、恢复 source header/affine、复制 corrected seg，并建立新的 synthetic ID。

V2 的数据身份是“新增训练病例”，只能追加到 train。

### 2.2 G1 缺失模态 V3

V3 根据真实 `t1n+t1c+t2f` 重建缺失或伪造的 T2W。它不是数据扩增，而是原病例修复。

G2 必须保留原病例 ID 和 nnU-Net ID，只替换 T2W，保持真实 t1n/t1c/t2f/seg 和原 master split。train completion 可用于训练；val/test completion 只用于原 split 的评估。

## 3. 数据身份与固定划分

### 3.1 Patient group

划分单位不是完整病例 ID，而是去掉末尾数字后缀的患者组：

```text
BraTS-MET-00001-000
BraTS-MET-00001-001
BraTS-MET-00001-002
-> BraTS-MET-00001
```

同组病例不得跨 train/val/test。

### 3.2 当前 authoritative artifacts

| 文件 | 含义 |
|---|---|
| `nnunet_case_mapping_master.csv` | 1295 例完整身份，含 265 个 completion 目标 |
| `nnunet_case_mapping_realonly.csv` | 1030 例 authentic-T2W baseline |
| `g1_v2_source_manifest.csv` | V2 source 审批表，823 行允许生成 |
| `splits_master_train_val_test.json` | master 1035/130/130 |
| `splits_final_train_val_test.json` | real-only 823/103/104 |

265 个 completion 目标在 master 中为 212/27/26。患者组 overlap 为 0。

### 3.3 Split 使用原则

1. master split 是病例身份的唯一来源。
2. real-only split 是 master 中 authentic-T2W 的派生视图。
3. V3 修复后，265 例回到 master 中原 split。
4. V2 augmentation 只追加到 master train。
5. synthetic 不进入 val/test。
6. 历史 S2 baseline 使用的旧 split 只能作为历史结果；若要与新 G2 数据做严格消融，必须在当前 master split 上重新建立 paired real-only baseline。

## 4. 输入契约

### 4.1 V2 raw contract

必须有：

```text
generation_config.json
BraTS-MET-xxxxx-xxx-t1n.nii.gz
BraTS-MET-xxxxx-xxx-t1c.nii.gz
BraTS-MET-xxxxx-xxx-t2w.nii.gz
BraTS-MET-xxxxx-xxx-t2f.nii.gz
```

配置至少记录：

```text
generation_run_id
generator_name
seed
diffusion_checkpoint_dir 或四模态 checkpoint
sampling_method
sampling_steps
source manifest
```

composer 输出必须增加：

```text
generation_log.jsonl
synthetic_generation_manifest.csv
<raw_id>/<raw_id>-t1n/t1c/t2w/t2f/seg.nii.gz
<raw_id>/<raw_id>-generation_support.nii.gz
```

### 4.2 V3 completion contract

run root 必须有：

```text
inference_run.json
generation_config.json
generation_log.jsonl
synthetic_generation_manifest.csv
```

每病例必须有完整四模态和 seg。配置必须记录 VAE、EncDec、BBDM checkpoint、`bbdm_s`、seed、source CSV 和固定 validation run。

## 5. QC 总体架构

QC 分为三个阶段，不能只看一个相似度指标。

### 5.1 A 阶段：技术硬门

任一失败直接 `rejected`：

1. 配置、manifest、log、checkpoint、seed 或 source metadata 缺失。
2. source 不在 master，或 V2 source 不是 authentic master train。
3. V3 source 不在 265 个 fake/broken T2W 清单。
4. V2 复用真实 ID，或 V3 创建新的 synthetic ID。
5. 必需 NIfTI 缺失、不可读、含 NaN/Inf 或常数图。
6. 病例内 shape、spacing、affine、orientation 不一致。
7. 与 source shape 不一致。
8. seg 非整数、标签越界、空病灶或明显在脑外。
9. V2 composition 后非 generation support 区域发生变化。
10. patient-group 或 split 泄漏。

### 5.2 B 阶段：图像质量复核

当前自动计算：

1. ROI boundary normalized MAE。
2. ROI boundary gradient discontinuity。
3. 综合 block artifact score。
4. 非 ROI 改动比例。
5. source/synthetic ROI SSIM。
6. 强度漂移 p1/p50/p99。
7. z 方向面积和强度平滑度。
8. 病灶数量、体积和大小分层。
9. 病灶落在脑区内的比例。
10. ET-T1C、SNFH-T2F、SNFH-T2W 对比度。
11. 多模态 ROI 相关性。

通用 synthetic intake 仍不内置 teacher。针对 G1 V3 阶段 5，已经提供独立的
`g2_s2_v3_teacher_eval.py` 和 `02_g2_v3_s2_teacher.slurm`，使用冻结的 Dataset263
real-only checkpoint 对同一 103 例进行成对 teacher 推理。它不会回写或伪造通用 intake 的
teacher 字段，也不能单独自动批准阶段 6。

当前没有在自动脚本中声称完成：

1. MS-SSIM。
2. medical FID/MMD。
3. 跨 run 精确或近似重复检测。
4. 放射科级主观质量结论。

未完成项保持空值或 `not_run`，不写常量占位值。没有人工或 teacher 审批时，技术通过病例为 `pending_review`。

### 5.3 C 阶段：训练价值验收

固定实验组：

```text
A real-only
B real + V3 completion
C real + accepted V2 augmentation
D real + V3 completion + accepted V2 augmentation
```

四组必须共享同一真实 val/test、相同代码和相同调参预算。

最终主指标：

1. ET/RC/TC/WT lesionwise DSC。
2. ET/RC/TC/WT lesionwise NSD。
3. ET/RC/TC/WT small-instance TP/FN/FP/F1。

图像 QC 证明“数据没有明显坏掉”，官方任务指标证明“数据对分割任务有用”，二者不能互相替代。

## 6. Release 状态机

| 状态 | 含义 | 可训练 |
|---|---|---|
| `rejected` | 硬门失败 | 否 |
| `pending_review` | 技术通过，等待人工、teacher 或批次审批 | 否 |
| `accepted_for_training` | train augmentation 或 train completion 正式批准 | 是 |
| `accepted_for_evaluation` | val/test completion 正式批准 | 否，只用于原 split 评估 |

审批必须来自 run root 的 `g2_approval_manifest.csv`。accepted manifest 是脚本派生结果，不允许人工直接改写。

## 7. V2 执行流程

```text
G1 V2 flat whole-shape output
  -> g2_v2_compose_augmentation.py
  -> full cases + source geometry + seg + support + run metadata
  -> g2_synthetic_raw_intake_qc.py --generation-mode full_generation
  -> rejected / pending
  -> 人工或 teacher 审批
  -> 重新 intake
  -> accepted_for_training
```

V2 synthetic ID 使用 `generation_run_id + synthetic_raw_id` 的稳定哈希，避免不同 run 从同一序号开始而冲突。

## 8. V3 执行流程

正式生成 265 例前，先对 103 例 fixed validation 执行 Stage 5 gate：

```text
G1 Stage 5 native-space reconstruction
  -> metrics.csv + spatial_audit.csv + synthesized/
  -> G2 paired image/lesion QC (spatial audit hard gate)
  -> frozen S2 teacher
  -> stratified montage review
  -> FINAL_GATE.json
  -> only approve_stage6 may start 265-case inference
```

`spatial_audit.csv` 必须与 metrics 病例完全一致，前景和病灶的 outside count 全为 0。
旧的 `reject_and_retune` gate 不能通过手工设置参数绕过。

```text
G1 V3 completion run
  -> g2_v3_completion_intake.py
  -> metadata + identity + geometry + image QC
  -> rejected / pending
  -> 人工或 teacher 审批
  -> 重新 intake
  -> train: accepted_for_training
  -> val/test: accepted_for_evaluation
```

物化时，仅 V3 T2W 可覆盖 master 中该病例的 T2W 路径。

## 9. 下游数据发布

统一通道：

```text
0000=t1n
0001=t1c
0002=t2w
0003=t2f
```

`g2_materialize_nnunet_dataset.py` 支持：

1. `real-only`：只发布 authentic-T2W baseline。
2. `completion`：发布 master，并用 approved V3 替换 265 例 T2W。
3. `real-synth`：在 completion 数据上追加 approved V2 train augmentation。
4. 多 accepted manifest。
5. nnU-Net view 和 case-folder view。
6. fixed split、dataset.json、物化 manifest和 integrity report。
7. 非空目录保护与显式 clean。

| 视图 | 下游 |
|---|---|
| nnU-Net raw | S2 |
| case-folder | S1、S3、S4、S5 |

## 10. 完整性检查

G2 内置检查每例四通道和一个 label、文件存在且可读、病例内几何一致、label 值域合法以及 fixed split 无病例 ID 重叠。

服务器安装 nnU-Net 后，再使用：

```bash
--run-nnunet-integrity
```

该选项调用 `nnUNetv2_plan_and_preprocess --verify_dataset_integrity`。`manifest-only` 只能做源文件预检，不能运行 nnU-Net integrity。

## 11. 批次报告

每个正式 run 必须报告：

1. G1 代码版本、checkpoint、seed 和参数。
2. source manifest 和 master split 版本。
3. 交付、成功 composition、失败、rejected、pending、accepted 数。
4. 硬拒绝原因分布。
5. 自动质量指标分布和异常病例。
6. 人工或 teacher 复核者、日期和理由。
7. materialization 与 integrity 结果。
8. 成对消融的官方任务指标。
9. 是否建议进入主训练方案。

## 12. 风险控制

1. 不接受未知 source。
2. 不接受 val/test augmentation。
3. 不接受 metadata 不完整批次。
4. 不接受手改 ID 或 split。
5. 不清空非空输出目录，除非操作者显式确认。
6. 不把本机 fixture 结果当正式影像验收。
7. 不把历史不同 split 的 S2 checkpoint 作为新 master split 的严格对照组。
8. 不把 leaderboard CSV parser 描述成官方 NIfTI evaluator。

## 13. 完成标准

1. master split 患者组泄漏为 0。
2. 两条 G1 产线使用独立 adapter。
3. 元数据缺失会硬拒绝。
4. V2 可恢复完整 geometry，V3 可保留真实身份。
5. 未计算 QC 项不再填伪值。
6. 所有病例有唯一 release 状态。
7. S1-S5 使用同一通道和 fixed split。
8. 真实批次通过完整性、人工/teacher 与成对消融验收。
