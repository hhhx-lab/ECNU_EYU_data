# S4 服务器运行手册

## 1. 当前定位

S4 是 SAM2-UNet / SAM 变体探索线。当前代码可以先做 real-only smoke test，但它内部仍使用自己的 RC-stratified split，不直接读取 G2 固定 split。因此：

1. S4 可以在 S2、S1 之后跑 smoke test。
2. 如果要做严格公平对比，后续必须再补 G2 fixed split adapter。
3. 当前 S4 结果不能直接和 S2/S1 real-only 主结果做最终结论对比。

## 2. 环境配置

先按同目录下的环境文件创建并自检环境：

```text
work_space/S4/docs/S4_experiment.txt
```

推荐 conda 环境名：

```text
CONDA_ENV=brats2026_s4
```

S4 Slurm 支持 `CONDA_ENV`、`VENV_DIR`、`PYTHON_BIN` 三种方式。服务器上如果 conda 不在 PATH，可以用 `VENV_DIR=/path/to/venv` 或 `PYTHON_BIN=/path/to/python` 覆盖。正式运行前至少确认 `torch`、`nibabel`、`einops`、`matplotlib`、`numpy`、`tqdm` 能 import。

## 3. 输入数据

S4 训练脚本扫描完整病例目录。推荐 real-only smoke test 输入：

```text
work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training/
```

每个病例必须包含：

```text
<case_id>-t1n.nii.gz
<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

S4 代码会自动跳过不完整病例；也就是说缺 `t2w` 的病例不会进入 S4 训练。日志会打印 skipped incomplete case directories。

通道顺序固定为：

```text
t1n, t1c, t2w, t2f
```

## 4. Slurm 运行命令

S4 的 Slurm 脚本在：

```text
work_space/S4/slurm/train_sam2unet_post.slurm
```

debug 试跑：

```bash
PROJECT_ROOT=/scratch/bf2260/ECNU_EYU_data
cd ${PROJECT_ROOT}/work_space/S4

sbatch --export=ALL,\
RUN_MODE=debug,\
PROJECT_DIR=${PROJECT_ROOT}/work_space/S4/code,\
TRAIN_DIR=${PROJECT_ROOT}/work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training,\
SAVE_ROOT=${PROJECT_ROOT}/work_space/S4/output,\
CONDA_ENV=brats2026_s4 \
slurm/train_sam2unet_post.slurm
```

full 训练：

```bash
PROJECT_ROOT=/scratch/bf2260/ECNU_EYU_data
cd ${PROJECT_ROOT}/work_space/S4

sbatch --export=ALL,\
RUN_MODE=full,\
PROJECT_DIR=${PROJECT_ROOT}/work_space/S4/code,\
TRAIN_DIR=${PROJECT_ROOT}/work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training,\
SAVE_ROOT=${PROJECT_ROOT}/work_space/S4/output,\
CONDA_ENV=brats2026_s4 \
slurm/train_sam2unet_post.slurm
```

如果环境不是 conda，也可以用：

```bash
sbatch --export=ALL,RUN_MODE=debug,PROJECT_DIR=...,TRAIN_DIR=...,SAVE_ROOT=...,VENV_DIR=/path/to/venv slurm/train_sam2unet_post.slurm
```

或：

```bash
sbatch --export=ALL,RUN_MODE=debug,PROJECT_DIR=...,TRAIN_DIR=...,SAVE_ROOT=...,PYTHON_BIN=/path/to/python slurm/train_sam2unet_post.slurm
```

## 5. Slurm 会做什么

1. 进入 `PROJECT_DIR`，也就是 `work_space/S4/code`。
2. 检查 `train_sam2unet_post.py` 和 `sam2unet_model.py`。
3. 检查 `TRAIN_DIR` 是否存在。
4. 设置 `SAM2UNET_*` 环境变量。
5. 运行 `train_sam2unet_post.py`。
6. 把日志写到 `${SAVE_DIR}/logs/train-<jobid>.log`。

## 7. 调参方式

Slurm 通过环境变量传参：

```bash
SAM2UNET_EPOCHS=450
SAM2UNET_WARMUP_EPOCHS=30
SAM2UNET_CHECKPOINT_INTERVAL=10
SAM2UNET_BATCH_SIZE=1
SAM2UNET_ACCUMULATION_STEPS=1
SAM2UNET_CROP_SIZE=96,96,96
SAM2UNET_NUM_WORKERS=4
SAM2UNET_LR=1e-4
SAM2UNET_MAIN_HEAD_LR=1e-4
SAM2UNET_RC_HEAD_LR=3e-4
SAM2UNET_RC_LOSS_WEIGHT=4.0
SAM2UNET_RC_THRESHOLDS=0.15,0.20,0.25,0.30,0.35,0.40,0.50
```

显存不足时：

1. 保持 `SAM2UNET_BATCH_SIZE=1`。
2. 先把 `SAM2UNET_CROP_SIZE` 改为 `80,80,80`。
3. 再把 `SAM2UNET_NUM_WORKERS` 降到 2。
4. 如果验证太慢，把 `SAM2UNET_CHECKPOINT_INTERVAL` 从 10 改到 20。

RC 检出差时：

1. 先看 `validation_rc_threshold_sweep.csv`。
2. 调 `SAM2UNET_RC_THRESHOLDS`，不要只固定 0.3。
3. 可试提高 `SAM2UNET_RC_LOSS_WEIGHT`，例如 4、6、8。
4. 注意 RC false positive 变多时需要降低阈值策略或加后处理，不要只看 Dice。

## 8. 运行后检查

```bash
squeue -u $USER
tail -f work_space/S4/output/debug_post/logs/train-<jobid>.log
tail -f work_space/S4/output/full_train_450/logs/train-<jobid>.log
```

日志里应看到：

```text
cuda available: True
Skipped ... incomplete case directories
RC-stratified split
Running full-volume validation
Saved validation Dice history
```

## 9. 注意事项

1. S4 当前是 smoke/exploration，不是最终公平对比主线。
2. S4 还没有接 G2 fixed split；严谨对比前不能把它和 S2/S1 的 fixed-split 结果直接下结论。
3. 不要用官方 validation/pseudo-test 调参。
4. 不要直接使用 G1 raw synthetic；必须等后续 synthetic manifest 和质量检查策略确认后再做 real+synth。
