S4 SAM2-UNet server environment
===============================

This file describes the environment and two Slurm jobs used by the S4
real-only baseline on the ECNU cluster.

Conda setup
-----------

The server Conda activation script is:

  /public/software/apps/miniconda3/etc/profile.d/conda.sh

The initial S4 debug job reuses the existing brats_swin environment. It must
provide torch, nibabel, numpy, einops, tqdm, and matplotlib. The Slurm script
checks these imports and CUDA inside the allocated GPU job. Do not install
packages inside a batch job.

If an import fails, create a dedicated brats2026_s4 environment interactively:

  source /public/software/apps/miniconda3/etc/profile.d/conda.sh
  conda create -n brats2026_s4 python=3.10 -y
  conda activate brats2026_s4
  pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
  pip install nibabel numpy einops tqdm matplotlib scipy

Do not use sudo pip or system Python.

Required run order
------------------

1. Prepare the authoritative G2 real-only fixed split. This scans raw data,
   prefers corrected labels, excludes invalid or incomplete cases, and creates
   only symlinks plus manifests:

  cd /public/home/zqchen/projects/ECNU_EYU_data/work_space/S4
  mkdir -p logs
  sbatch slurm/00_prepare_g2_realonly_fixed_split.slurm

2. Wait for that job to reach COMPLETED. Its log must show non-zero train, val,
   and test counts. The output root is:

  work_space/G2/results/materialized_s4_realonly/

3. Submit the default S4 debug job. It uses at most 20 train and 20 validation
   cases, runs two epochs, and performs full-volume validation:

  cd /public/home/zqchen/projects/ECNU_EYU_data/work_space/S4
  mkdir -p logs
  sbatch slurm/train_sam2unet_post.slurm

4. Only after reviewing debug timing and outputs may a formal job be submitted.
   A full job requires an explicit epoch budget:

  sbatch --export=ALL,RUN_MODE=full,SAM2UNET_EPOCHS=<approved_epoch_budget> \
    slurm/train_sam2unet_post.slurm

Why 450 epochs is not a default
--------------------------------

Each S4 epoch scans all fixed-split train cases. After warmup, each epoch runs
both a main and an RC phase, so 450 epochs means roughly 870 training passes
over the train set plus periodic full-volume validation. It is not a two-day
default. Estimate real wall time from the debug job before selecting the
formal epoch budget and Slurm time limit.

Outputs and acceptance checks
-----------------------------

Preparation output:

  work_space/G2/results/materialized_s4_realonly/

Debug output:

  work_space/S4/results/debug_post/

Formal output:

  work_space/S4/results/full_train_<epochs>ep/

The debug run is acceptable only when its log contains:

  CUDA available: True
  G2 fixed split: ... train / ... val / ... locked test
  Running full-volume validation
  Saved validation Dice history
  Saved best_combined_model.pth

The expected artifacts are config.json, g2_fixed_split.json,
validation_dice_summary.csv, validation_dice_per_case.csv,
validation_dice_history.csv, best_main_model.pth, best_rc_model.pth,
best_combined_model.pth, latest_checkpoint.pth, and logs/train-<jobid>.log.
