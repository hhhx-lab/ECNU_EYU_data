# S4 SAM2-UNet 服务器运行手册

## 1. 当前实验口径

S4 是 BraTS-MET 的四模态 3D SAM2-UNet 分割线。正式 real-only 基线必须读取 G2 物化的固定病例目录，而不是直接把任意 raw 目录交给训练脚本。S4 只从 `train` 学习、在 `val` 选择 checkpoint，`test` 始终锁定且不会创建 DataLoader。

每个病例必须包含：

```text
<case_id>-t1n.nii.gz
<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

标签只能是 `0..4`，依次对应 background、NETC、SNFH、ET、RC。

默认 Slurm 使用 `brats_swin`，并在 A100 节点内检查 `torch`、`nibabel`、`numpy`、`einops`、`tqdm`、`matplotlib` 和 CUDA。缺包时不要在 batch job 中安装，应先按同目录 [S4_experiment.txt](S4_experiment.txt) 创建、验证独立 `brats2026_s4` 环境。

## 3. 第一步：物化固定划分

提交位置与脚本：

```bash
cd "${S4_ROOT}"
mkdir -p logs
sbatch slurm/00_prepare_g2_realonly_fixed_split.slurm
```

`00_prepare_g2_realonly_fixed_split.slurm` 使用 `cpu_96G`，完成以下工作：

1. 扫描 `${RAW_DATA_ROOT}` 和 corrected label 目录。
2. 使用官方 fake/broken T2W 清单建立 real-only mapping。
3. 自动跳过缺文件、缺 T2W、仍有非法标签的病例。
4. 按 G2 patient-group fixed split 建立 `train/val/test` 的 symlink case-folder view。
5. 写入 mapping、split、materialization manifest、integrity report。

输出位置：

```text
${PROJECT_ROOT}/work_space/G2/results/materialized_s4_realonly/
├── Dataset264_BraTS2026_MET_RealOnly_S4/
└── BraTS2026_MET_RealOnly_S4_case_folders/
    ├── train/
    ├── val/
    └── test/
```

检查：

```bash
squeue -u "$USER"
tail -n 80 logs/s4_prepare_g2_<jobid>.out
```

只有日志打印 `fixed_split_case_counts` 且三个 split 都非零时，才可进入下一步。

## 4. 第二步：提交默认 debug 训练

```bash
cd "${S4_ROOT}"
mkdir -p logs
sbatch slurm/train_sam2unet_post.slurm
```

脚本 `train_sam2unet_post.slurm` 默认 `RUN_MODE=debug`，使用一张 A100、20 个 train + 20 个 val、2 epoch。它会在第二个 epoch 开启 RC phase，并做一次完整体积 sliding-window validation。这个 job 的作用是验证环境、数据视图、内存、checkpoint 和指标输出，不是正式结果。

实时查看：

```bash
squeue -u "$USER"
tail -f logs/s4_sam2unet_<jobid>.out
tail -f results/debug_post/logs/train-<jobid>.log
```

debug 必须出现以下内容：

```text
CUDA available: True
G2 fixed split: ... train / ... val / ... locked test
Running full-volume validation
Saved validation Dice history
Saved best_combined_model.pth
```

若有 `NaN`、`Inf`、OOM、label 越界或 split overlap，停止在 debug 阶段修复，不能继续提交正式训练。

## 5. 正式训练和 450 epoch 约束

禁止直接执行未指定 epoch 的 `RUN_MODE=full`。脚本会拒绝这种提交，以避免误启动 450 epoch。

450 epoch 是极重的预算：前 30 epoch 为 main warmup，之后每 epoch 都有 main 与 RC 两个训练 phase；因此约等于 `30 + 2 x 420 = 870` 次完整训练集 pass，并且每 10 epoch 做一次 full-volume validation。它绝不是两天的合理默认值。

debug 完成后，从日志计算每个完整 epoch 和一次完整 validation 的 wall time，再明确选择预算：

```bash
cd "${S4_ROOT}"
mkdir -p logs
sbatch --export=ALL,\
RUN_MODE=full,\
SAM2UNET_EPOCHS=<已批准的epoch数>,\
FIXED_SPLIT_ROOT="${PROJECT_ROOT}/work_space/G2/results/materialized_s4_realonly/BraTS2026_MET_RealOnly_S4_case_folders" \
slurm/train_sam2unet_post.slurm
```

正式输出会写到：

```text
work_space/S4/results/full_train_<epochs>ep/
```

## 6. 调参和结果

常用参数通过 `sbatch --export=ALL,...` 覆盖，固定 split 不得改变：

```text
SAM2UNET_BATCH_SIZE=1
SAM2UNET_ACCUMULATION_STEPS=1
SAM2UNET_CROP_SIZE=96,96,96
SAM2UNET_NUM_WORKERS=4
SAM2UNET_LR=1e-4
SAM2UNET_MAIN_HEAD_LR=1e-4
SAM2UNET_RC_HEAD_LR=3e-4
SAM2UNET_RC_LOSS_WEIGHT=4.0
SAM2UNET_RC_THRESHOLDS=0.15,0.20,0.25,0.30,0.35,0.40,0.50
```

OOM 时先保持 batch=1，再将 crop 调成 `80,80,80`，最后把 worker 降到 2。不要通过改 train/val/test 划分或拿 locked test 调参来解决问题。

关键输出：

```text

g2_fixed_split.json
g2_train_audit/label_stats.json
g2_val_audit/label_stats.json
validation_dice_summary.csv
validation_dice_per_case.csv

best_rc_model.pth
best_combined_model.pth

```
