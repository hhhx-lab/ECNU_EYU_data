# S1 服务器运行手册

## 1. 当前结论

S1 当前先跑 real-only baseline。这里的 real-only 不是随便扫描全部原始数据，而是：

1. 直接扫描服务器上的原始 raw data。
2. 自动跳过缺 `t2w` 或缺任一必要文件的病例。
3. 由 G2 raw intake 脚本生成 real-only mapping 和固定 train/val/test split。
4. 只把 train+val 建成 S1 训练 view。
5. internal locked test 只写清单，不参与训练、预处理、调参。
6. 不使用 G1 T2W completion 输出。
7. 不使用 G1 diffusion synthetic 输出。

## 2. 服务器默认路径

下面命令里的 `PROJECT_ROOT` 是服务器上的项目根目录。当前 Slurm 示例默认：

```bash
PROJECT_ROOT=/scratch/bf2260/ECNU_EYU_data
```

如果服务器实际 clone 到别的位置，提交时用 `PROJ=/真实项目根目录` 覆盖。

## 3. 输入数据

S1 Slurm 首先读取原始数据：

```text
work_space/G1/data/raw/MICCAI-LH-BraTS2025-MET-Challenge-Training/
```

然后自动运行：

```text
work_space/G2/code/g2_build_realonly_from_raw.py
```

生成下面两个给 S1/S2/S3 共用的轻量文件：

```text
work_space/G2/results/manifests/nnunet_case_mapping_realonly.csv
work_space/G2/results/splits/splits_final_train_val_test.json
```

不完整病例会写入：

```text
work_space/G2/results/manifests/realonly_skipped_incomplete_cases.csv
```

每个病例至少包含：

```text
<case_id>-t1n.nii.gz
<case_id>-t1c.nii.gz
<case_id>-t2w.nii.gz
<case_id>-t2f.nii.gz
<case_id>-seg.nii.gz
```

```bash

```

## 5. Slurm 会做什么

脚本位置：

```text
work_space/G1/code/brats2025-latent-ensemble-synthesis-main/slurm/05_s1_realonly_nyu.slurm
```

执行步骤：

1. 检查 S1 repository、raw data、G2 raw intake 脚本、conda 激活脚本是否存在。
2. 激活 `brats2026_s1` 环境。
3. 从 raw data 刷新 G2 real-only mapping 和 split。
4. 缺 `t2w` 或缺任一必要文件的病例只记录到 skipped CSV，不进入训练。
5. 读取生成后的 G2 split。
6. 根据 G2 mapping 建立 S1 训练 view。
7. 把四个模态和有效 seg 以 symlink 方式放入 view。
8. 在 view 内生成 `tumor_label.nii.gz` 和 `rc_label.nii.gz`。
9. 审计 view 里的病例和标签。
10. 启动 `trainer_v1_final.py --config configs/multitask_v1_full.yaml`。

## 7. 运行后检查

先看作业状态：

```bash
squeue -u $USER
```

看日志：

```bash
tail -f ${PROJECT_ROOT}/logs/s1_realonly_<jobid>.out
tail -f ${PROJECT_ROOT}/logs/s1_realonly_<jobid>.err
```

日志里应该看到：

```text
valid_cases=...
skipped_cases=...
train: ...
val: ...
test locked: ...
audit finished
trainer initialized
```

如果当前 raw data 中完整病例数仍为 1295，默认 20% internal locked test、train-pool 20% validation 的结果应是 train 829、val 207、test 259。若有病例缺 `t2w` 被跳过，数量会按实际完整病例数自动重算。

训练输出至少应出现：

```text
work_space/S1/results/realonly/checkpoints/
work_space/S1/results/realonly/tensorboard/
```

## 8. 调参位置

主要改：

```text
work_space/S1/brats2026_multitask_S1_v2/repository/configs/multitask_v1_full.yaml
```

优先级：

1. 显存不够：先把 `train.batch_size` 从 2 改成 1。
2. loss 震荡：把 `train.lr` 从 `0.0003` 改成 `0.0001`。
3. crop 太大：最后才改 `train.patch_size`，不要一开始就大幅降。
4. 续训：设置环境变量 `S1_RESUME=/path/to/latest.pth`。

## 9. 注意事项

1. 不要用 `scripts/10_create_full_split.py` 生成随机 split 来做正式 real-only baseline。
2. 不要把 internal locked test 放进 `real_only_cases`。
3. 不要直接使用 G1 raw synthetic；必须等后续 synthetic manifest 和质量检查策略确认后再接入。
4. S1 推理当前输出 tumor 和 RC 两个结果，最终 BraTS 单文件 label map 还需要融合步骤。
