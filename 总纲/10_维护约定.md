# 总纲维护约定

建立日期：2026-09-19。总纲是长期入口，不再新建互相竞争的“最终总总结”。

## 每次项目工作结束前

1. 阅读总纲README、相应模块专题及已知缺口；确认实验身份、病例集合和正式状态。
2. 新实验或新模型只追加独立批次；不改旧失败证据、不重写原SHA清单、不把最新结果覆盖旧选择。
3. 若新增训练、评价、模型选择、数据版本、失败恢复或搬迁，更新相关中文专题和 `维护/知识登记.json`。登记精确路径、日期含义、模型SHA、数据split、状态、证据入口和解释边界。
4. 在 `更新记录.md` 追加这次改变，不把旧描述删除后装作从未发生。
5. 运行生成器创建新时间戳索引，然后运行检查。只有检查pass才能说“总纲已同步”。

从项目根运行，使用现有Conda base，仅Python标准库，不安装任何依赖：

```bash
conda run --no-capture-output -n base python -B 总纲/维护/catalog.py build --reason "本次变化的简短说明"
conda run --no-capture-output -n base python -B 总纲/维护/catalog.py check
```

查某个文件、checkpoint或实现符号：

```bash
conda run --no-capture-output -n base python -B 总纲/维护/catalog.py find "checkpoint_final"
conda run --no-capture-output -n base python -B tools/project_paths.py "旧路径"
```

维护工具自测：

```bash
conda run --no-capture-output -n base python -B -m unittest discover -s 总纲/维护 -p 'test_*.py'
```

这不是后台自动同步；更新索引不授权登录服务器、训练、部署或提交作业。按 [Agent.md](../Agent.md)，每次完工验证后须中文提交、SSH推送当前分支，记录改动与验证，及时收口工作区。

## 人工结论与机器索引分工

| 内容 | 谁负责更新 | 不能做什么 |
|---|---|---|
| 01–09专题、关键数值与研究结论 | 人工按引用原证据复核 | 不能从文件名猜成功，也不能让脚本自动宣布最佳模型 |
| `维护/知识登记.json` | 人工登记批次上下文、状态与证据；修改后推进reviewed_at时间 | 不能把FAILED改成pass而没有独立新证据 |
| 完整文件树、全部文件/目录CSV、分页用途、数据模型实体 | `catalog.py build`生成 | 不手改快照；不遗漏隐藏文件和历史区 |
| 当前索引入口 | 生成器指向最新完整快照 | 不删除旧快照或递归复制旧快照内容 |
| 原实验日志、runtime、SHA、failed/complete标记 | 只读引用 | 不为使总纲整齐而修改这些证据 |

来源文件hash发生变化时，生成器会要求先人工复核并更新 `reviewed_at`，再重建索引。新增批次需要人工登记；没有登记的文件仍会按路径规则收录，但不会被自动赋予实验成功状态。

## 覆盖与检查的准确含义

- 枚举项目根内全部物理目录、普通文件和符号链接，不跟随链接。历史775个链接对象仍保留，只记身份，不扫描外部目标。
- 每个文件记录当前相对/绝对路径、模块、所属单元、用途说明、说明依据、类型、大小、mtime、权限；非敏感且不超过2MiB文件计算SHA256。
- 大文件只做元数据登记；不假装完整内容hash已复核。权重不反序列化，NIfTI不逐体素加载。
- Python只解析AST顶层定义；小JSON读取顶层schema；CSV/TSV读取列名与行数；Markdown只提取标题。日志和二进制不做全文摘录。
- `.git`内部完全排除枚举；`.env`、私钥、凭据及工具隐私配置只记路径和元数据，不读取内容、不计算内容hash、不在总纲复制值。
- 本机索引也覆盖忽略的测试/依赖/大文件，只表明本地位置存在；Git发布边界由忽略规则及处置清单说明，不能以索引覆盖替代备份或完整运行包。清理须先区分可再生缓存与实验原件，保留路径/SHA/恢复依据。
- 所有索引快照及当前入口按“路径级对象”收录，不对自身大小/mtime/SHA作递归校验。旧快照不再复制旧快照的正文，只会被新目录列出路径。
- `check`检查路径集合全覆盖、重复行、缺少描述、文件变化、专题链接和已引用证据SHA漂移；G1/S2的新增一级实验批次未人工登记也会阻止pass。它不是训练测试，不替代科学验收。
- 解析错误会出现在 `parse_error_paths`；文件仍收录并注明未解析。科学文档或新源码出现错误应单独处理，不能静默视为已读懂。

未来移动或新增文件后，请更新总纲再结束任务。若因证据缺失不能完成，只能明确记录缺口，不能把“尚未确认”改成“没有发生”。
